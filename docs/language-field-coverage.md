# Language × output-model field coverage

For every language the CLI supports, which fields of each per-file output model its extraction code actually writes. Generated by static analysis of `src/extractors/plugins/**` (TypeScript compiler API): object-literal construction — including conditional spreads — plus property assignment, with checker-based type classification. Shared helpers in `plugins/shared/` are attributed to the languages that use them. Not-written fields are then classified **D** (deliverable — the concept exists in that language and is extractable; a real gap) or **N** (no such concept in that language/framework; a legitimate absence).

**Legend:** ✓ = written · `D` = deliverable (not written, but the concept exists and is extractable — a real gap) · `N` = not deliverable (no such concept in that language/framework — a legitimate absence) · ✗ = a *required* field that is missing (a real gap) · `ts`/`regex` = parsing strategy.

## Key findings

- **Model-level gaps are legitimate.** `RouteInfo` is absent for 31 languages (C, C++, SQL, Prisma, Erlang, Objective-C, Haskell, all template languages, QML/XAML, …) — they have no HTTP routing. `ExportInfo` is absent for bash/fsharp/r/julia/ocaml; `ClassInfo`/`PropertyInfo` for bash.
- **Language-specific optional fields** (written by ≤3 languages, expected): `FunctionInfo.urlTemplate`/`requestDescriptor` (JS), `explicitInterface` (C#); `ClassInfo.typeParameters` (**C# only** — Java/Kotlin/TS handle generics differently), `embeds` (Go), `mixins` (PHP/Ruby/Dart); `PropertyInfo.readAccessor`/`commandHandler` (Pascal/.NET).
- **Fields set by core, not plugins** (the static read can't see core post-passes, so they show as D in the tables; core applies them at runtime): `FunctionInfo.doc`/`ClassInfo.doc` (doc-comment pass — written wherever the language manifest declares `docComments`; the non-program languages that don't are N), `RouteInfo.redirectsTo`/`webhook`/`consumed`/`implementedBy`/`resolvedBy`/`basePath`/`testCoverage`/`pathUnresolved` (server-redirects, webhook-routes, client-proxies, route resolvers, template resolution, test-coverage join).

> This is a static read of the plugin source. It captures what extraction code writes, not runtime-conditional branches or core post-passes.
