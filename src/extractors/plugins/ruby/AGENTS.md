# Ruby plugin

Reads Ruby source (Rails, Sinatra and Rack apps included) through the regex path (`RegexLangSpec`, `family` script, keyword-delimited blocks), with a tree-sitter-ruby second pass for taint; the Rails view reader in `erb/` is described in the last section (the `erb/` folder has no `AGENTS.md` of its own). Each file's header comment holds its mechanism; this page is the map and the rules that span files.

## Rules a change must respect

- Regex path: [index.ts](index.ts) exports the spec; routes go through `RegexLangSpec.extractRoutes`. `indentBased` is true, but Ruby supplies its own block ends ([blocks.ts](blocks.ts) `blockEnds`: heredocs, `%w[]`, `=begin`, `#{}`, regex literals blanked; a method-level `rescue` stays in its method).
- Control flow: `meta.regexControlFlow` is a keyword scanner (`blockDelta`, `blockClose`, `armBlocks`, `inlineGuard`) gated against tree-sitter-ruby, a dev dependency (about 98% of real Rails methods come out the same shape).
- Taint ([taint.ts](taint.ts)): `regexTaint` (`{ gate, taint }`), run by `file-analyzer.ts` on a flat copy of the tree-sitter tree (grammar in `dist/grammars`, the `taint` feature switches it off).
- Discovery: extension-less `#!` scripts are Ruby (manifest `shebangInterpreter`). A Gemfile re-admits `bin/` only beside `app/` or `lib/` (`sourceDirs` `requiresAnyOf`); one naming `sinatra` or `rack` (`markerMatches`) re-admits it with neither. A file declaring no class, module or route runs its top-level statements as `<setup>` (`topLevelCallsInTypelessFiles`), minus `typelessSetupExcluded` (specs and tests).
- Performance: a pattern built from a name is built only after a substring test on that name passes (`assignmentsOf`); whitespace runs are anchored to horizontal whitespace and read once (a 160,000-space line cost 24 s once).
- Mixins: a bare call inside a method is the class's own member, then its bases' and the ONE mixed-in module that defines it. `untypedReceiverMembers` (`find_by`, `save`, `where`) on a receiver nothing types link to nothing — the framework's, not the one class defining the name; a namesake class of another namespace (`Overlay::Club`) may be mixed in unseen.
- Imports: `require`/`require_relative` ([require-paths.ts](require-paths.ts)) also tries every extension of the importer's family. [autoload.ts](autoload.ts): `autoloadedFiles` is Zeitwerk's rule (`Club::MatchReport` → `club/match_report.rb` under `app/*/`, `concerns/`, `lib/`); `importsNameDirectories` resolves a package import to the one directory `packageDirectory` names. `ImportInfo.aliases` maps renames. `typesBeyondDirectory` (Ruby and Rust): the directory's declarations lead, and a qualified name or several real declarations that the writing file does not own refuse. `typeNamedByReceiver`: `match_report` → `MatchReport`; a receiver's name is evidence only as the segment right before the method (`club.league.relegated?` is called on `league`).
- Ruby `::` paths (`lexicalConstants`) name a class by its path in the class id; a file that declares two classes of one name (`Garage::Table`, `League::Table`) keys each of them by its declaration besides the plain name (`classKey`, see the core `AGENTS.md`), so a constant path the call writes (looked up through the caller's nesting) or a typed receiver reaches the member of the class declared there (a path naming no class of that file, or a class reopened in it, keeps the plain name); a namespace written relative to the caller (`Routes::Fixtures` inside `module League`) falls back to the ONE declared class whose name ends that way. Top-level `NAME = Foo.new` constants are `moduleBindings` (`extractModuleBindings`): `moduleBindingsFollowImports` makes them visible to the files that `require` it, a few files deep; one inside `module League` is `League::NAME`, and `ModuleBindingInfo.lexical` lets the bare name stand for it inside that module's body.
- Shape facts: `Score = Struct.new(:home, :away) do … end` and `Data.define(…)` are classes of the constant ([constant-class-headers.ts](constant-class-headers.ts)); `self.class.x` in an instance method is named through the class (`Club.x`); a method whose last statement is a call chain carries it as `returnedFrom` (`def build_car; Car.find_by(…); end`, an implicit return) and `@car = build_car` is a one-step own-method chain core types through it; `attr_writer`/`attr_accessor` synthesize `x=`; each method's first `@x` write and each writer method (`attr_writer`, `def x=`) states an `init` declaration, and `ClassInfo.fieldValues` also holds a variable assigned another variable; a Sorbet `sig { returns(Score) }` is the method's `returnType`.
- `raise T` names the constant, `raise "text"` no type; fieldWrites state `@x`, `@@x`, `self.x =` through a writer method, `@club.x` and a typed receiver. A thrown type written with a namespace (`Net::ReadTimeout`) binds by its last segment only through a qualifier the project backs (`qualifierBacksClass`).
- Local types: `localTypes[].from` for `c ? A.new : B.new` and `if … elsif … else … end` (each arm a `from` chain `A.new()`, marked with `choice`; `chainPoint` goes on from the instance when the class head is followed by one of `constructorCalls`). A local assigned once from a reader chain off a typed local (`got = lk.score`) is typed by the chain's return. A YARD/Sorbet `@param` types a formal only while the body does not assign the name again (except `x = x.reload`/`.dup`/`.clone`/`.itself`/`.freeze`).
- Associations read through the model's ancestors (nearest wins) and through a concern another concern includes (`moveConcernRelations`).
- Editions: `Api::ClubsController.prepend_mod_with('Api::ClubsController')` → `Enterprise::`/`EE::`/`JH::Api::ClubsController` (`ClassInfo.mixins` kind `prepend`) answers an action before the class itself; `super` in a prepended module's method is the prepending class's method of that name (`prependeeTarget`).
- Click to data: an api-call joining a route whose handler is an action a mixin defines for several includers lands on that includer's own `route:` symbol, the row found by normalized path (`{id}` and `:id` meet). `describe Club` in a spec file with cases marks the files declaring `Club` tested (basis `described`).
- A route nothing names carries `RouteInfo.derivedName`; `RouteInfo.registeredAt` (`{ file, line }`) records the router line whose link source is the controller method, which rename plans list; a guard a route inherits comes from a base controller's `before_action` (route resolver, joined as `viaMiddleware`); `rails-action-exits` is a per-action fact of what the action does (`render`/`redirect_to`/`head`/`send_*`/`respond_to`).
- Reachability: declarative spec from the reachability kit; Ruby reaches by constant name through autoload, so an import graph cannot prove files unreachable; libraries (gemspec) are not judged dead.

## ERB (Rails views, `erb/`)

[erb/](../erb/) is a small plugin; its resolver and reader facts live here.

- A POST form with no action is marked `InteractiveElementInfo.ownViewPost`; core's own-view-posts pass gives it `POST <path>` when every route rendering the screen is at one path.
- [own-view.ts](../erb/own-view.ts) (`rails-own-view` route resolver) sets a view's `renderedBy`; a `before_action` that halts is not seen there. Views are resolved by [rails-view-resolver.ts](../erb/rails-view-resolver.ts).
- `link_to`/`button_to`/form helpers name a route helper as `route:<helper>` (`route:club_players`) in `request.target` and `ScreenInfo.navigatesTo`; so `link_to "Squad", club_players_path(@club)` reaches that route's screen; the screen flow resolves it through `RouteInfo.name` (an `as:`) and else `RouteInfo.derivedName`. A view's URL-less POST form is a `submit` self-edge, the one self-edge the navigation map keeps.

## How core passes read it

- Conditional initializers (`c ? A.new : B.new`, an `if` expression) are read as `from: "A.new()"` chains marked with `localTypes[].choice`.
- `params[:id]` is a `request-param` origin (path and query merged) matching either binding.
- A `redirect_to x_path` helper resolves only by name: a stated one, else the derived one.
