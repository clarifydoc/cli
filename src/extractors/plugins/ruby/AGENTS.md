# Ruby plugin

Reads Ruby source (Rails, Sinatra and Rack apps included) through the regex path (`RegexLangSpec`, `family` script, keyword-delimited blocks), with a tree-sitter-ruby second pass for taint; the Rails view reader in `erb/` is described in the last section (the `erb/` folder has no `AGENTS.md` of its own).

## Files and front end

- Regex path: [index.ts](index.ts) exports the spec; routes go through `RegexLangSpec.extractRoutes`. `indentBased` is true, but Ruby supplies its own block ends (see Structure).
- **Block ends.** [blocks.ts](blocks.ts) `blockEnds` blanks non-code (heredocs, `%w[]`, `=begin`, `#{}`, regex literals) and closes `def`/`class`/`if`/`do` at their `end`, so a method-level `rescue` stays in its method and a heredoc at column 0 does not end the class. `callSourceLines` is `rubyCallLinesOf` over the code lines `rubyCodeLinesOf` gives (heredocs, `%w[]`, `=begin` blanked; `#{}` read as code). A file with no `lambda do` / `-> do` line scans its blocks once (a statement's block ends are read only for those lines).
- **Chains continued on a line opening with a dot.** A line opening with `.name` or `&.name` after a line a chain can continue from (`Club` / `.where(league: id)` / `.order(:name)`) is read with the chain so far carried onto it (`Club.where(league: id)`, then `Club.where(league: id).order(:name)`), so each hop keeps its own line and receiver; a line ending in `,`, an open bracket, an operator, `do` or `end` carries nothing.
- **Control flow.** `meta.regexControlFlow` uses a keyword scanner: `blockDelta` says what each line opens (`if` at a statement's start, a trailing `do`), `blockClose` what closes (`end`), `armBlocks` (a `case`'s `else` is an arm) and `inlineGuard` (`stmt if cond`). It is gated against tree-sitter-ruby, a dev dependency (98.9% of one real Rails repository's methods and 98.0% of a second's come out the same shape).
- **Taint** ([taint.ts](taint.ts)): the meta states `regexTaint` (`{ gate, taint }`, no `ast.taint` hook); `file-analyzer.ts` parses a file whose source matches `gate` once more with tree-sitter-ruby (shipped in `dist/grammars`; the `taint` feature switches it off) and runs the shared `handlerTaint` walk, never on a test or generated file or a tree with syntax errors, reading a flat copy of the tree. Handlers are every method of a controller (superclass or `app/controllers/`) and `get "/x" do` blocks; keyword arguments (`where(name: params[:x])`) are dropped; a method that assigns its own `params` has none. A heredoc opening is read as the `heredoc_body` that follows its statement, so interpolation in `find_by_sql(<<~SQL)` reaches the sink, and a heredoc chained into text-keeping calls (`<<~SQL.strip`, `.squish`) is its body. Measured: one finding on one real Ruby repository after the false ones drove the propagator and guard rules.
- Discovery: extension-less `#!` scripts are Ruby files (manifest `shebangInterpreter`). A Gemfile re-admits `bin/` only beside `app/` or `lib/` (`sourceDirs` `requiresAnyOf`); a Gemfile naming `sinatra` or `rack` (`markerMatches`) re-admits `bin/` with neither.
- A file that declares no class, module or route runs its top-level statements as `<setup>` (`topLevelCallsInTypelessFiles`), minus `typelessSetupExcluded` (specs and tests, which their runners read).
- Performance: a pattern built from a name is built only after a substring test on that name passes (`assignmentsOf`). A Ruby line of 160,000 spaces cost 24 s once: whitespace runs are anchored to horizontal whitespace and read once.

## Structure

- Constant headers: a header that wraps over several lines, opens its `do` on a later line, or is a bare `Class.new(Base)` is joined into one line for class extraction ([constant-class-headers.ts](constant-class-headers.ts), line numbers kept).
- `Score = Struct.new(:home, :away) do … end` and `Data.define(…)` are classes of the constant (fields as readers, writers on a Struct, the block's `def`s as methods).
- `include Singleton` gives a class-level `instance` returning an instance of the class the call names (`FunctionInfo.returnsInstance`: a class-level `self` return that is not the class object), so `LeagueRegistry.instance.register` reaches the subclass's own method and never types a subclass as its base. It is untyped otherwise: a subclass's `instance` is its own. A Sorbet `sig { returns(Score) }` (or `T.nilable(Score)`) is the method's `returnType`.
- `self.class.x` in an instance method is named through the class (`Club.x`) whether or not the class declares `self.x`, so the linker walks its bases and extended modules like any class-method call (a library's `self.class.get` links to nothing).
- A method whose last statement is a call chain off a class or off the instance's own method (`def build_car; Car.find_by(…); end`, an implicit return) carries it as `returnedFrom` like a memoizing reader; `@car = build_car` (a bare name that is no local) is a one-step own-method chain core types through it. A last statement of anything else (a branch, a parameter, a literal) states nothing.
- A one-line `def` states value flow from the body after its signature. `attr_writer`/`attr_accessor` synthesize `x=`.
- Each method's first `@x` write and each writer method (`attr_writer`, `def x=`) states an `init` declaration beside it: a class declares an instance variable by assigning it. `ClassInfo.fieldValues` also holds a variable assigned another variable (`@a`).
- Ruby `::` paths (`lexicalConstants`) name a class by its path in the class id; a namespace written relative to the caller (`Routes::Fixtures` inside `module League`) falls back to the ONE declared class whose name ends that way.
- Top-level `NAME = Foo.new` constants are `moduleBindings` (`extractModuleBindings`): `moduleBindingsFollowImports` makes them visible to the files that `require` it, a few files deep; one inside `module League` is `League::NAME`, and `ModuleBindingInfo.lexical` lets the bare name stand for it inside that module's body, before a top-level namesake.

## Imports and scope

- `require`/`require_relative` ([require-paths.ts](require-paths.ts)): a relative import written without an extension also tries every extension of the importer's family.
- Autoload ([autoload.ts](autoload.ts)): `autoloadedFiles` is Zeitwerk's rule (`Club::MatchReport` → `club/match_report.rb` under `app/*/`, `concerns/`, `lib/`), so the language is never import-blind. `importsNameDirectories` resolves a package import to the one directory the language's `packageDirectory` rule names.
- Own resolver for the name an aliased import was exported as; `ImportInfo.aliases` maps renames.
- `typesBeyondDirectory` (Ruby and Rust): a type is looked up beyond its directory — the directory's declarations lead, and a qualified name or several real declarations of a name that the writing file does not own refuse.
- `typeNamedByReceiver`: `match_report` → `MatchReport`; a receiver's name is evidence only as the segment right before the method (`club.league.relegated?` is called on `league`).
- A Ruby `raise T` names the constant, `raise "text"` no type; fieldWrites state `@x`, `@@x`, `self.x =` through a writer method, `@club.x` and a typed receiver.

## Linking rules

- **Mixins.** A bare call inside a method is the class's own member, then its bases' and the ONE mixed-in module that defines it (Ruby `include`); `untypedReceiverMembers` (`find_by`, `save`, `where`) on a receiver nothing types link to nothing: the framework's, not the one class defining the name.
- **Syntax calls** ([syntax-calls.ts](syntax-calls.ts), run from `extractValueFlow`; `club.name = x`, `club + other`, `club[1]`). An attribute assignment `recv.x = v` is a call of `x=`; a binary operator (`+ - * / % << >> < > <= >= == != <=> ===`, `!=` run as `==`) and an index (`recv[k]` → `[]`, `recv[k] = v` → `[]=`) a call of the class's operator method. They are recorded as `CallInfo.syntax` under `receiver.member` (`club.name=`, `club.+`, `club.[]=`), one per name per function, only for a receiver whose HEAD can be typed (`self`, an instance variable, a parameter, a local with a `localTypes` entry), possibly followed by a path of readers and calls (`repo.find(1) + other` is `repo.find.+`; a setter off any reader path, an operator or index only off a call's result). Never an index chain, a literal-bound local or the framework's `params`/`session`/`options` hashes. The linker keeps one only where the receiver's declared type, or the enclosing class for `self`, gives the member (no guess by name: a namesake class behind an untyped receiver, a class with no such operator and plain numbers, strings and hashes draw no edge); a setter written again in the same function keeps its later lines in `CallInfo.siteLines`, one field-write site each. A syntax call is linked only through the receiver's declared type or the enclosing class, never by a guess of its name, in `resolveCallToDefinitionBody`, as a `mapMember` call is.
- **A setter no method serves** (`club.status = x`) is no call: the linker types its receiver like any call's and hands the site (`AttributeWriteSite`, `buildSymbolLinks`' fourth argument) to [core/attribute-writes.ts](../../../core/attribute-writes.ts), which, after the entity passes joined schema columns onto the models, records a `FieldWriteRow` where the class or a base declares the attribute as a property.
- **Local types.** `localTypes[].from` for `c ? A.new : B.new` and `if … elsif … else … end` (one expression per branch, each arm a `from` chain, written `A.new()`; `chainPoint` goes on from the instance when the class head is followed by one of `constructorCalls`) marks arms with `choice`. A local assigned once from a reader chain off a typed local (`got = lk.score`) is typed by the chain's return; one assigned again, or a parameter, stays untyped.
- **Documented types.** A YARD/Sorbet `@param` types a formal only while the body does not assign the name again — any `x = …` except the identity-keeping `x = x.reload`/`.dup`/`.clone`/`.itself`/`.freeze`; then the local's own initializer applies, or nothing.
- **Request attributes** (Rails `Current`): `Current.league = League.find(…)` (a constant finder, an `@ivar` the class assigns a model, or `Current.league.clubs.find(…)`) is kept per class in `fieldValues` under `Current.<attr>`. `RubyEntityExtractor.reconcileProject` types `Current.<attr>` when all assignments agree (any other assignment, or two models, types nothing) and, with no assignment, by the model the attribute is named after (`DataSourceInfo.entityConfidence: "INFERRED"`). `Current.<attr>.<assoc>.<verb>` reads `<assoc>` on THAT model, which settles a name two models declare with different targets (four-segment shape only; concern and inherited associations fall back to the global name). `Current.user = user` takes the chain of the local the method assigned earlier (`user = Player.find(…)`; a parameter or `nil` states nothing). An `@x = param.reload` takes the model a YARD `@param` / Sorbet `sig` gives the parameter (every method declaring that name must agree). `@club = @league.clubs.find_by(…)` takes `clubs` on the model `@league` holds (an owner nothing types makes the variable untyped, whatever else assigns it).
- **Associations** read through the model's ancestors (the nearest declaration wins) and through a concern another concern includes (`moveConcernRelations` follows `include` from module to module to the models).
- **Concerns** ([concerns.ts](concerns.ts)): a concern's bare verbs (`update!` in a `module X; extend ActiveSupport::Concern`) carry `DataSourceInfo.mixinSelf`: inside a method core binds them to the model each resolved call runs on (core's `core/mixin-self.ts`: a route's `model.update_badges` through the controller's typed reader keeps that model as the call's `receiverType`); an untyped call binds none; in the concern's body (an `included do` callback) the entity pass makes them one row per including model. A concern's `model.member` call through a memoizing reader (`def model; @model ||= @x; end`, or the endless `def model = @model ||= @x`) becomes the call of the model's member when `@x` is typed where it is assigned (a model constant, a one-target association, through other variables).
- **Editions.** `Api::ClubsController.prepend_mod_with('Api::ClubsController')` → `Enterprise::`/`EE::`/`JH::Api::ClubsController` (`ClassInfo.mixins` kind `prepend`) answers an action before the class itself; `super` in a prepended module's method is the prepending class's method of that name (`prependeeTarget`).
- **Gem actions.** A controller override that calls `super` records a call named `super`; [route-anchor.ts](route-anchor.ts) gives its route the gem action's model access (Administrate CRUD by the controller's name). A `mount_devise_token_auth_for 'Model'` route carries a `rails-devise-model` route fact (the model and the access its gem action has) that anchors the same way when the mapped model is one class of the project. `devise_for :players` draws the routes of the modules the model's own `devise :…` line enables (on the model or an ancestor; [devise-routes.ts](devise-routes.ts) joins the router's `rails-devise-for` fact with the model's `rails-devise-modules` one); nothing for a model whose `devise` line the project does not state.
- **Click to data.** An api-call joining a route whose handler is an action a mixin defines for several includers (a Rails concern) lands on that includer's own `route:` symbol, the row found by normalized path, so `{id}` and `:id` spellings meet.
- **Spec describes.** `describe Club` in a spec file with cases marks the files declaring a class of that name tested (basis `described`); framework wiring (a prepended mixin, callbacks) has no written call.
- Own-view join (see ERB) follows a controller's `extends` to the action it inherits and refuses when that action answers the request itself (`redirect_to`, `render`, a halting `before_action`) or two bases leave it in doubt.

## Value flow ([value-flow.ts](value-flow.ts))

- Reads `method(:save)`, instance variables, hash/array literals, constants through `moduleValueFlow` (the spec's `extractModuleValueFlow`), `each` block variables, and invokes `.call` / `.()` (never on a receiver whose type is stated).
- A brace lambda or proc held in a value (`-> { save }`, `lambda { Club.close }`, `proc { … }`) and the `do … end` forms (`lambda do |x| … end`, `-> do … end`, whose statement runs through the block's `end`) stand for the project functions the body calls, at most four (counted by core); a block handed to a method or a loop's `do` is no value. A closure written as an argument (`schedule(callback: -> { on_full_time })`) stands for the project functions its body calls and reaches the callee's invoke.
- A keyword argument `schedule(callback: method(:f))` is an `arg` with `name` (index -1); core binds the formal whose `ParamInfo.argumentLabel ?? name` it names. Ruby states `argumentLabel` `"_"` for a positional formal (`def schedule(callback = nil)`, `opts = {}`), so only a keyword formal takes a keyword argument; an unknown name binds nothing.
- A `&x` block argument is an `arg` named `&` that binds the `&blk` formal (`ParamInfo.argumentLabel` `&`), and on `each`/`map`/… also an `invoke`; `&:sym` states nothing.
- A list or map handed to a parameter passes its elements (`arg` `elements: true`; core joins the caller's `<arg>.[]` to the formal's).

## Routes and frameworks

- A route nothing names carries `RouteInfo.derivedName`, the helper Rails derives: `resources :clubs` → `clubs`/`club`/`new_club`/`edit_club`, nested `club_players`, namespaces `admin_cars`, `news_index` when plural equals singular, `get 'standings'` → `standings`, `root`. A `scope as:` prefixes it; a `concern` or `shallow` block gives none; a route with `as:` states `name` instead. Only URL helpers read it (the server-redirect pass for `redirect_to clubs_path`, and the `route:` navigation targets), after every stated `name`, in the caller's own sub-project first.
- Inside `controller :x do`, `on: :member`/`:collection` hang off the enclosing resource, `path: 'crest'` replaces a symbol route's segment and `module: :staff` puts the controller in that module.
- A `redirect_to x_path` helper resolves only by name: a stated one, else the derived one.
- `RouteInfo.registeredAt` (`{ file, line }`) records the line of a `get 'clubs', to: 'clubs#index'` / `resources :players` row whose link source is the controller method: rename plans list that line's span (`clubs#index`, `only: [:index]`, `action: :index`).
- A guard a route inherits comes from a base controller's `before_action` (route resolver, joined as `viaMiddleware`).
- **Halting filters** ([caller-halts.ts](caller-halts.ts)). A `before_action` whose method body halts a caller it cannot identify or permit is a guard whatever its name, unless the name says it is a switch or optional (`ensure_x_enabled!`; `namesNonCaller`). The halt — a 401/403 (`head`, `render … status:`), a `raise` of a NotAuthorized/Unauthorized/AccessDenied/Forbidden-named error or a `redirect_to`/`redirect_back` — must be governed by a condition that tests the caller's identity or permission, with the polarity that halts when the check fails: the statement modifier or the directly enclosing `if`/`unless` (its `else` the opposite test; nothing deeper, no unrelated outer condition), or an unconditional halt that follows only `return if <caller ok>` guard clauses. The tested thing is the bare caller (`current_user`, `logged_in?`, `signed_in?`, `authenticated?`, a credential-looking `session[:player_id]`/token header, `authenticate_with_http_token`, `.nil?`/`.blank?`/`.present?` of them), an instance variable this filter set from a token/credential lookup (`@kit_app = KitApp.find_by(access_token: …)` / `find_by_token` / `from_token`, then `@kit_app.blank?`), or a permission, role or ownership predicate on it (`current_user.admin?`, `can?(…)`, `policy(…).x?`, `current_user.role == …`, `<record>.owner == current_user`). Never a guard: a state predicate on an already identified caller (`active?`, `confirmed?`, `suspended?`), a condition on params, a feature switch, a constant or another record's state, a blank-check on an ivar no token lookup set (`find_by(name: …)`), the wrong polarity (`redirect_to … if current_user.present?`), an unconditional halt; when in doubt it is no guard. The method carries the `halts-caller` decorator and `guardForFilter` takes it as the check, in the class, in a concern it includes and in an ancestor.
- `rails-action-exits` is a per-action fact of what the action does (`render`/`redirect_to`/`head`/`send_*`/`respond_to`).

## API calls and config

- [service-config.ts](service-config.ts): `config/*.yml` with ERB `ENV.fetch`, `config.x.*`, `ENV[...]`, `Rails.configuration.x.k` (`serviceConfig`); a config entry names the variables that override it in `ConfigEntry.envNames`. Faraday callers are covered by the labelled fixture `test-fixtures/sample-microservices` (with an `archive` decoy).

## Data access and entities

- Rails schema: the plugin parses `db/schema.rb` during `extract` (stashing tables on `FileAnalysis.railsSchemaTables`, [schema.ts](schema.ts)) and `RubyEntityExtractor.reconcileProject` attaches those columns to the model entities that live in other files.
- `Current.<attr>`, association and concern rules are under Linking.

## Reachability

- Declarative spec from the reachability kit ([reachability.ts](reachability.ts)): Ruby reaches by constant name through autoload, so an import graph cannot prove files unreachable; libraries (gemspec) are not judged as dead.

## Gotchas

- `untypedReceiverMembers` (`find_by`, `save`, `where`) must keep an untyped receiver unlinked; a namesake class of another namespace (`Overlay::Club`) may be mixed in unseen.

## ERB (Rails views, `erb/`)

[erb/](../erb/) is a small plugin; its resolver and reader facts live here.

- **POST form with no action posts to its own page.** `form_with`/`form_tag` with keyword options only (no `url:`/`model:`/positional/splat, POST) and a native `<form method="post">` are marked `InteractiveElementInfo.ownViewPost` (a GET never; a template expression in the attribute is a URL and never marks it). Core's own-view-posts pass gives it `POST <path>` when every route rendering the screen is at one path.
- [own-view.ts](../erb/own-view.ts) (`rails-own-view` route resolver) gives every Rails view's screen `renderedBy` = the ONE GET route of its `Ctl#action` when the action renders implicitly (no `rails-action-exits` fact and no such call), else nothing; this is what lets a link to the page draw an edge on the screen map. A `before_action` that halts is not seen there. It follows a controller's `extends` to the inherited action and refuses when that action answers the request itself or two bases leave it in doubt.
- `link_to`/`button_to`/form helpers name a route helper as `route:<helper>` (`route:club_players` for `club_players_path`) in `request.target` and `ScreenInfo.navigatesTo`; the screen flow and navigation pass resolve it through `RouteInfo.name` (an `as:`) and else `RouteInfo.derivedName`, so `link_to "Squad", club_players_path(@club)` reaches the screen of that route, and a helper a rename replaced (`fixture_path` after `as: :games`) reaches nothing.
- A Rails view's URL-less POST form posts to the action that renders it implicitly (a `submit` self-edge, the one self-edge the navigation map keeps).
- Views are resolved by [rails-view-resolver.ts](../erb/rails-view-resolver.ts).
