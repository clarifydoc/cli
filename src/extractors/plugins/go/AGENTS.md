# Go plugin

Reads `.go` files through a regex `RegexLangSpec` ([index.ts](index.ts)) with an ANTLR front end (`meta.antlr`) supplying functions and calls; a file the parser reports syntax errors for keeps the regex reading. Parser internals (decision settling, the grammar) are in [parsers/AGENTS.md](../../../parsers/AGENTS.md).

## Packages and imports

- A Go package is its directory. The manifest sets `importsNameDirectories` + a `packageDirectory` rule ([package-directory.ts](package-directory.ts)): an import is the repository package's `go.mod` module path (or a `replace` to a local directory) plus the directory; the standard library and downloads are no directory. Else the directory whose path ends with the longest run of the import's segments (a tie is no edge), narrowed to the files declaring a name the importer uses, tests excluded. Dead code reads these edges as reachability, so a phantom fan-out hides real gaps.
- Imports are structural (`extractImports`): only inside `import` declarations, aliases kept as the specifier (a per-line `"…"` pattern took every string line for an import and missed `alias "path"`). Dot imports are `ImportInfo.inScope`.
- `directoryNamesShared` makes every file of a directory one package for names: package variables, bare calls and functions. A file's `package` clause is `FileAnalysis.packageClause`; two files of one directory whose clauses differ (`package club` and the external test package `package club_test`, `sameDirectoryPackage`) share no function, binding or package variable, and a test file's binding never reaches production code.
- `directoryScope`: a bare call a file does not define resolves into the caller's package directory — the one non-test sibling file declaring it.
- Unique-global-leaf evidence is the files of every package any non-test file of the caller's package imports. A receiver that is a package no directory holds (`strings.Cut`) is vetoed.
- `typesSpanFiles`: methods beside their struct in other files of the directory make one type (`ClassRef.parts`); a package-qualified type (`models.Club`) states nothing for member effects. `ClassInfo.kind: "interface"` with `structural: true` marks Go interfaces.
- `valuePathsNameNoType`: `a.b.C.m(` never names a type, so a `receiverCut` name (`s.Controller.Delete(` read as `Controller.Delete`) is refused by the ClassName.method guess (a namesake class is no reading of a field's unresolved type), and a held noise member (`c.Status.String(`) called through a path from a typed head is restored (`restoreTypedReceiverCalls`). Both front ends name a path from a local — a range variable, an initialized local — by its whole path (`c.Status.String`, `x.League.Close`) as they do from a receiver or parameter, so the linker types the local (`localTypes`) and follows the fields.
- A `receiverCut` call has no head the caller binds: Strategy 2, `chainReceiverType`, `receiverTypeRefuses` and the name guess's declared type all leave it alone, so the caller's own `league` field neither types nor contradicts it.
- A process Go starts (`exec.Command`) is an import carrying `executes: true` and shares nothing.
- Dead code: [reachability.ts](reachability.ts) is a convention spec; `unitOf` makes a package one unit and a module path is an `extend` rule. Go packages outside `internal/` are a library's API and not judged.

## Types, receivers and locals

- **Method sets follow the receiver kind** ([addressed-types.ts](addressed-types.ts)). `FunctionInfo.pointerReceiver` marks `func (c *T)` (both front ends read it from the declaration line); `FileAnalysis.addressedTypes` lists types a file uses by address — `&T{…}`, `*T` outside a receiver, `new(T)`, `&x` of a local or parameter declared `T` (an `&x` it cannot type adds every value type the file names). With `structuralMatch.receiverKinds` the interface map leaves a pointer-receiver method out of the method set of a type no file addresses, so a value-only type implements nothing needing it and is never fanned out to; an embedded type always counts as addressed. The addressed-type reader reads value locals and value types only when an `&x` of a value exists.
- A typed chain follows promoted fields and embedded interfaces. Multi-value returns (`c, err := repo.Find(1)`) type the first result by the declared results.
- A `from` may be a call chain (`club.Address().City()`); `range` over a chain of calls and fields (`league.Club(1).Players()`) types the loop variable by the element.
- Alias `q := p` / `&p` is `LocalType.aliasOf`.
- Function-literal parameters (`run := func(g *Garage) { g.Open() }`, `func(s *Store) { s.Save() }(nil)`) are soft `localTypes` of the function holding the literal ([literal-params.ts](literal-params.ts)); a name two literals type differently, or one a local/parameter/receiver of the function also binds, stays untyped.
- A body-only local declared in several blocks with different stated types (`s := NewClub()` in one `if`, `s := NewPlayer()` in the next) is untyped function-wide; `typeBlockLocalCalls` ([classes.ts](classes.ts)) gives each call on it the `receiverType` of the declaration its block sees, a block stating none leaving its call as it was. It indexes the body's identifiers once.
- A `type X` declared in a function body hides the package's `X` from that line on (`hideShadowedTypes`, after the struct-literal pass; both front ends).
- A local from a generic constructor with type arguments (`NewBox[int]()`) drops the list when every element is written as a type (`dropTypeArguments`); `handlers[k]()` stays an index call.
- **Struct literals construct.** Go and Rust call `withStructLiteralCalls` ([../shared/struct-literals.ts](../shared/struct-literals.ts)) from `postProcessFunctions`/`postProcessClasses`: each literal in expression position (`Club{…}`, `models.Club` as written) becomes a call carrying `CallInfo.construction: "literal"`, linking `instantiates` to the struct itself (`constructionLink`, never a `New…` function). Never for a block opener (`if x {`, `-> Club {`), a collection literal (`[]Club{}`) or a pattern.
- Package variables (`var store = NewStore()`, `var cache Cache`) are `FileAnalysis.moduleBindings`: `type` as written, or `from` (the initializing call chain) when only a call states it; core types a `from` binding by the callee's declared result. Locals, parameters and any name the body binds (`FunctionInfo.boundNames`, which covers Go's declared names and literal parameters) shadow it. A bare name no local, parameter or field takes reads the file's `moduleBindings`, then those of its sibling files and their functions. A bare call of a function a sibling file declares is followed for the result type (`packageScoped` language).
- Member effects ([member-effects.ts](member-effects.ts)): Go states field writes (`fieldWrites`) and no thrown types. A bare assignment is a candidate package variable (`fieldWrites[].package`), listed as `via: "package"` with `class` the package name only when exactly one file of the package declares it (`FileAnalysis.packageVariables`, `extractPackageVariables`). A Go thrown type never meets another language's namesake (`throw new Error` in TypeScript vs a Go `Error` struct): resolution stays inside the writer's family.

## Routes, middleware and handlers

- Routes come from `extractRoutes` in [routes.ts](routes.ts) (Go muxers and framework registrars); [huma.ts](huma.ts) reads Huma operations. A per-line rule loop first tests one alternation of the words every rule names after a `.` and skips the line otherwise (`extractGoRoutes`).
- **Handler factories.** A handler-building call's argument is a value (so the factory is the handler) when it is a name the ENCLOSING function declares — parameter, receiver, local — or a package `var`, or `x.y` where `x` is such a value, `y` a struct field the file declares and no method of the file is named `y` (`handlers.List(s.db)`; `s.Ping` stays a method value). The set is per function, never file-wide (`valuesAt`).
- **Router functions.** Routes registered by a function on the router it is handed (`func Register(r *gin.RouterGroup)`) are `owner: "fn:<name>"` rows plus `router-call` facts, composed by [router-fn-resolver.ts](router-fn-resolver.ts) with [../shared/router-functions.ts](../shared/router-functions.ts). The mount site's guards (`api := r.Group("/api", auth.Required()); clubs.Register(api)`) become `RouteInfo.inheritedMiddleware`, resolved in the mount's file and joined as `viaMiddleware`. A route prefix from a constant (`router.Group(config.ApiUri)`) is filled by a route resolver through the module-value pass ([module-values.ts](module-values.ts)).
- `RouteInfo.middlewareCalls` lists the functions a router's middleware registration names (`Group("/x", auth.Require(db))`, `Use(mw)`, chi `With(mw)` — the middleware of the route's own group only); the linker resolves them as it resolves a handler (a link from the route's own symbol), and a flow whose witness leaves the route through one carries `viaMiddleware`.
- **Huma.** `RouteInfo.registrar` (the function whose body declares a Huma operation, [huma-resolver.ts](huma-resolver.ts)) is part of `routeIdentityKey` and of the route's symbol (`route:GET /items @registerClubs`, `routeSymbolName` in [route-symbol.ts](../../../core/route-symbol.ts)), so two registrars of one file never share a symbol, reach or data-access row.
- **Request binding.** A handler built for a type it binds the request into carries `RouteInfo.handlerTypes`; the type's tagged fields are `PropertyInfo.boundFrom` (Huma `input *ClubInput` with `path:"club"`, `param:"club"` tags), from which parameter-column origins flow through `receiver-field` / `param-field` origins. The request body is read by [request-access.ts](request-access.ts) and [request-schema.ts](request-schema.ts); a bound struct's non-numeric fields are taint sources (see Taint).
- Thrift: generated stubs (Go `NewClubServiceClientFactory`) ride the gRPC hooks (`grpcStubService`/`grpcServiceOf`); a Go stub TYPE (`ClubServiceClient`) counts only in a file importing the Thrift runtime or a package the project generated from a `.thrift` (a `gen-go/` path, or a package declaring `XClient` beside `XProcessor` — `core/grpc-clients.ts` hands the stub hook every analyzed file as a third argument, and `firstStub` prefers a certain answer). Handlers the generated code does not name — `NewClubServiceProcessor(&clubHandler{})` — are `thrift-handler` route facts joined by the `thrift-handlers` resolver.

## Data, clients and messaging

- Data access: [data-sources.ts](data-sources.ts), ORM entities in [entities.ts](entities.ts), xorm in [xorm.ts](xorm.ts), column resolution in [struct-columns.ts](struct-columns.ts). A filter on a whole object (`DataSourceInfo.whereObjects`: xorm `Where(cond)` of a condition parameter, a bean read into — `s.Get(c)`, `club = *c; s.Get(&club)` — less the fields written first, `except`) names the field carried in it (`builder.Eq{"id": clubID}`, `&Club{ID: id}`) as the column unless a `whereFields` row of the statement already names that value's column. A struct member settles to its column first — the xorm `'club_id'` / GORM `column:` tag of the struct, found beside the statement before a same-named one elsewhere, else the mapper convention `OtherClubID` → `other_club_id` (`whereFields[].fieldOf` until the entity pass rewrites `field`).
- Client bases ([http-clients.ts](http-clients.ts)): resty `SetBaseURL`/`SetHostURL`, a URL-named field or assignment holding a literal or `os.Getenv` state `httpClientRegistrations`; the api-call row names its receiver `client`. Labelled fixture decoy: one `archive` caller.
- Messaging: Go `paho` MQTT is `topicSyntax: "mqtt"`; `SubscribeMultiple(map…)` gives one row per topic; a topic held in an exported `pkg.Name` is a `targetRef` row. Dapr pub/sub is read when the file imports the SDK. Scheduled jobs (cron/gocron registrations naming a function) are read by [scheduled-jobs.ts](scheduled-jobs.ts); a versioned Go file under a migrations directory is a migration ([migration-files.ts](migration-files.ts)).
- OSV advisories (`--osv`): Go's `ecosystem_specific.imports` names vulnerable functions (`PackageManagerSpec.advisoryFunctions`), giving `reach` per route; `go.mod` is read by [package-manifests.ts](package-manifests.ts).
- Test coverage: Go cover profiles map to `testCoverage` per file and function.

## Value flow (ANTLR reading only; the regex fallback states none)

[value-flow.ts](value-flow.ts) states `ParsedFunctionSpan.valueFlow` / `ParsedStructure.moduleValueFlow` for: locals, pairs, method values, function-typed fields (an `invoke` on `c.onSave()` only where the file declares the field function-typed), `map`/slice literals and `append`, `range`, package variables and factory returns.

- A package variable a function writes is a `ValueCell.module` cell in that function's facts (a parameter or local may flow into it; the file's `<setup>` states the name, with a self-`copy` marking the name bound); a package variable declared without a value (`var hooks []func()`) is bound by a module self-copy.
- A bare call of a name the file neither binds nor declares states an `invoke` on `{ name, package: true }`; core joins the cell (`ValueCell.package`, `ValueFlowHost.sharedModuleFiles`) to the ONE sibling file whose module facts bind it, and drops it when none or several do. A sibling function of that name keeps its name-tier link; an ordinary call to a sibling function looks the same, so a bare `hook()` call of such a name states no invoke (a plain-name invoke leaves the name tiers). A cell flagged `package` is left to the name tiers by `valueFlowInvokeSites`.
- A name written or read as `v`, `v[k]` or `range v` that the file neither binds nor declares is flagged `ValueCell.package`.
- `m[k]` with an identifier key is read by the grammar as a type instantiation (`typeArgs` on the operand), so a single type argument is an index with an unknown key (its element member `[]`).
- A package variable declared in another file is not seen by the writer's own facts.

## Taint

Go has no `ast.taint` hook: the meta states `regexTaint` (`{ gate, taint }`) and a file whose source matches `gate` is parsed once more with `tree-sitter-go` (shipped in `dist/grammars`, switched off by the `taint` feature) for the shared [handlerTaint](../shared/handler-taint.ts) walk — never a test or generated file or a tree with syntax errors.

- [taint.ts](taint.ts) builds its spec per file: source reads only on the context/request parameter names the file declares (`c.Query(…)`, `r.URL.Query()`); SQL sinks only on a receiver that names a database handle (`db`, `tx`, `conn`, `gorm`…), never `repo.Query`.
- `binds`: a call that fills a variable from the request without assigning it (`c.ShouldBindJSON(&req)`, `json.NewDecoder(r.Body).Decode(&req)`) makes the struct's non-numeric fields `req.Field` sources. `stringReads` is Go's own.
- Zero findings on five reference Go repositories is the measured bar: precision first, every finding is an accusation.

## Tests and tooling

- [test-command.ts](test-command.ts): `go test -run`. A testify suite is a file importing `suite` whose top-level `TestX` runs `suite.Run(t, new(X))`/`&X{}` ([test-suites.ts](test-suites.ts), `extractTestSuites`; a type two runners run states none); it reaches `TestTarget.suites`, so `goTestCommand` selects a suite's methods as `-run '^TestXSuite$' -testify.m '^(TestA|TestB)$'` and keeps the subtest filter `-run '/^(TestA)$'` without it (`-testify.m` is a defined flag only in a binary linking testify).
- [build-constraints.ts](build-constraints.ts) sets `FileAnalysis.excludedFromDefaultBuild`: a file a Linux/amd64 build leaves out (GOOS/GOARCH file suffix, a false `//go:build` or `// +build` line); a tag the target does not fix makes the line undecided and the file is kept. [project-commands.ts](project-commands.ts) states how the project builds and tests.

## Layer 2 and control flow

- LSP: gopls (Docker image under `docker/go/`; `indexDelayMs` 5 s). Control flow is the approximate regex tier (`meta.regexControlFlow`), marked `approximate`.

## How core passes read it

- Param columns: an object handed to a generic handler that calls a method on it (`DoUpdate(ctx, obj CObject, a)` → `obj.Update`) goes on through the call site's `interface-redirect` link to that type's method, its field now the receiver's.
- A local declared by type and assigned on each arm (`var api Api; if … { api = a() } else { api = b() }`) needs no `choice`: the declared type states the receiver.
- A field receiver typed `*http.Error` keeps its qualifier through `writtenTypeName` (`receiverTypeName` drops it); the qualifier binds a project class only where the project backs it (`qualifierBacksClass`).
