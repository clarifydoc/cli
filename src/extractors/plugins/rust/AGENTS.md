# Rust plugin

Reads `.rs` files through a regex `RegexLangSpec` ([index.ts](index.ts)) with an ANTLR front end (`meta.antlr`, [antlr.ts](antlr.ts)) supplying functions and calls; a file with syntax errors keeps the regex reading. Parser internals (the SLL settling, lexer retyping) are in [parsers/AGENTS.md](../../../parsers/AGENTS.md). `rust` has no `ast.taint` hook; see Taint.

## Source preparation

- [source.ts](source.ts) blanks the text of every string literal that spans lines or holds a Rust item on one line (`"pub struct User { … }"`, `b"…"`, `r"…"`/`r#"…"#`/`br##"…"##`), keeping line structure and columns, so code-shaped text in a fixture never reads as functions, structs and calls. One-line strings stay (routes, URLs, SQL are read from them); a quote in a comment or a character literal (`'"'`) opens nothing; a lifetime `'a` is code ([lexicon.ts](lexicon.ts)).
- `#[...]` attributes ride the spec's `attributeLine`: an own-line attribute (`#[serde(rename = "x")]`) becomes a `decorators` entry on the item below it.

## Modules, `use` paths and imports

- `importsNameDirectories`: a package import resolves to the directory the `packageDirectory` rule names. `Cargo.toml` is a sub-project marker and a package manifest ([package-manifests.ts](package-manifests.ts)).
- **Module resolution** ([module-resolver.ts](module-resolver.ts), the plugin's `resolveImport`): `crate::a::b` is under the importing crate's `src/` (the `lib.rs`/`main.rs` directory) as `a/b.rs` or `a/b/mod.rs`; a file under a crate's `tests/`, `benches/` or `examples/` is in a crate of its own, so `crate::` is that directory; `self::`/`super::` are beside/above; `other_crate::m` is the workspace crate whose directory is named so (`-` for `_`). A module that does not declare the name but glob-re-exports a child (`pub use chat_sql::*`) answers with that child, one re-exporting the item by name (`pub use inner::sweep;`) with the module that declares it. A name the path itself ends with is also tried as the item of its parent module. A glob (`use crate::schema::*`, a workspace crate's `x::*`) resolves through these rules; `self`/`super` globs are not followed. `use crate::league::{Table}` finds the file declaring each name through glob re-exports.
- `importConfinement`: a `crate::` path is confined to the importing crate's own `src/`; a namesake outside is no answer, but a module re-exporting another crate's item, module or glob hands it over.
- A `#[path]` module's import source `./x.rs::inner` resolves `inner` below the file; a path-loaded file holds its children as a `mod.rs` does (a `mod inner;` it declares is `inner.rs` beside it, which no `foo/inner.rs` answers, so its `pub use inner::X;` re-exports are followed). Index-module stem for URL helpers: `directoryIndexStems` is `mod`.
- Renames (`use … as`) are `ImportInfo.aliases`. An import of a package a manifest declares or of the standard library never binds a project file by names.
- **Inline `mod` blocks.** A function in an inline `mod pitch { fn helper() {} }` that shares its name with another function of the file (the block's own, a sibling block's, the file level's) is named by its module path (`pitch::helper`, `nameDuplicatesByModule`); a function with no namesake keeps its bare name, since another file reaches it by that name through its `use`. A bare call inside a block is the block's own item, else the one item a glob of the block brings (`use super::*` in a `mod tests` nested in `mod pitch` is `pitch`'s, `use self::kit::*` a nested module's), never the parent module's namesake. `pitch::helper()`, `self::`/`super::` and a `use … as` alias of an inline module resolve to the one function declared directly in that block (`inlineModuleMember`, run in the plugin's `postExtract`, both front ends alike).
- The manifest's `importedItemName` hook names the function an import path's inline modules give it (`use crate::util::pitch::helper; helper()` → `pitch::helper`, never a file-level namesake), asked for a bare cross-file call and a glob import.
- **Path calls.** `pathCallTypesNeedScope` (`separator`, `selfTypes`, `typeSegment`): in `Garage::park()` the `CallInfo.receiverType` keeps the module path written before it (`crate::garage::Garage`), all three readers (ANTLR, ANTLR macro, regex) alike. The type binds only when the caller's file declares it, an import brings it in (named, alias, glob, a re-export or a `pub type X = path::X;` alias up to three hops) or the written path reaches it; a method of an `extension` part (an `impl` block in another file) is in scope when the type's declaration is; the link is labelled `class-name`, not `injection`.
  - A capitalized segment before the type (`Shape::Kind::make()`, `pathCallTypesNeedScope.typeSegment`) makes an associated-type path no import or module binds: left unlinked — unless the segment names a module file of the project (`mod Util;` in `Util.rs`, `namesModuleFile`), when it is a module and the type binds through it.
  - A written path to a free function of such a module (`crate::Util::tune()`, `capitalizedModuleCall`) is read as the lowercase spelling is (`target` the path, `member` the function, `moduleMember`) when no project type bears the name; a bare `Util::tune()` stays a type call.
  - A path call through a project module (`util::format()`, not `std::`/`core::`/`alloc::`) is `keepNoise`: it names its function whatever the leaf.
- A `typesBeyondDirectory` language (Rust, Ruby): a type is looked up past its directory, the directory's declarations first; a qualified name or a name with several real declarations none of which the writing file owns refuses. `relativeTypeQualifiers` (`crate`/`self`/`super`) name no module, so `crate::Club` stays the project's own.
- Hierarchies: an `impl` block in another file or crate is `ClassInfo.extension` — a part of the type, never its declaration; a trait's default method is the ONE interface method the type (or one of its extension parts) implements. `transparentTypeWrappers` lists `Arc`/`Box`: `Arc<dyn T>` is `T`.

## Calls, receivers and locals

- **Struct literals construct**: `Club { … }`, `league::Club { … }` become `construction: "literal"` calls through `withStructLiteralCalls` ([../shared/struct-literals.ts](../shared/struct-literals.ts)) (impl methods live in classes); never for a block opener (`impl Club {`, `if x {`) or a pattern (`Club { name } =>`).
- Alias `let q = p` / `&p` is `LocalType.aliasOf` (flow order in [../shared/alias-flow.ts](../shared/alias-flow.ts)).
- `for` over a field or call types the element ([collection-element.ts](collection-element.ts), element types in [element-types.ts](element-types.ts)).
- Rust's wasm bridge: a rule with `decorator.classes` (wasm-bindgen) also binds the classes carrying the attribute (`#[wasm_bindgen] struct`, `js_name` honoured) with their constructor and methods; the plugin hands an exporting `impl`'s attribute to each of its methods, and an `impl` in another file joins the struct's class; a multi-line `#[wasm_bindgen(…)]` on an `impl` reads like the one-line form. [foreign-bindings.ts](foreign-bindings.ts) states the generator configuration core joins: flutter_rust_bridge (`flutter_rust_bridge.yaml` beside a Flutter app's pubspec: each module of `rust_input` is written to `dart_output`, public functions in lowerCamelCase) and wasm-bindgen through wasm-pack (a `wasm-pack build <crate> --out-dir <dir>` package script: the crate's `#[wasm_bindgen]` functions and those of the project crates it links, named by `js_name`, in the module `<dir>/<crate_name>.js`).

## Member effects

[member-effects.ts](member-effects.ts) states `fieldWrites` and no thrown types. Writes through `self.x`, `self.field.x`, a typed parameter or local; a field behind a shared cell (`self.stats.borrow_mut().goals += 1`, `club.lock().unwrap().name = n`) or a deref (`*self.count += 1`) is a write of that field (`RefCell`/`Mutex`/`RwLock` are transparent wrappers of a declared type). A `static mut` written bare is a `package` write joined within its own file; one written through its module (`crate::stats::TOTAL += 1`, `stats::TOTAL = 0` after `use crate::stats;`) or bare after `use crate::stats::TOTAL;` is a `package` write whose `receiver` is the module path — core resolves it with the language's `resolveImport` to the one file that must declare the variable (`moduleVariableHome`), never a namesake module's.

## Routes, clients and data

- Routes: [routes.ts](routes.ts) (axum, actix-web, rocket attribute routes). Cross-file composition by route resolvers: axum `.nest("/api", api::routes())` and actix `.configure(routes::cfg)` whose callee lives in another file ([nest-resolver.ts](nest-resolver.ts): per file the nests/configures with their scope prefix, the fn each route line is declared in and the `use` renames; chained, so a nest inside a nested fn composes); Rocket `mount("/api", …)` bases followed module by module through `routes![…]` lists, appended route functions and `pub use … as …` renames ([rocket-mounts.ts](rocket-mounts.ts); a base spelled `[basepath, "/api"].concat()` is its literal part).
- Request schemas: [request-schema.ts](request-schema.ts); handler parameters in [params.ts](params.ts).
- Event dispatch: a plugin registering a handler per event of its enum (`AFPlugin::new().event(FolderEvent::CreateView, create_view_handler)`) joins a generated Dart call `<Enum><Variant>` to the handler the same crate defines under that name ([event-dispatch.ts](event-dispatch.ts), `AfDispatchResolver`).
- Client bases: [service-config.ts](service-config.ts) states `serviceConfig.baseRefOf` only. A base expression that OPENS with `env::var("X")` / `std::env::var_os` is an `env` ref, without the `.unwrap_or("http://…")` fallback (a host the deployment does not name would read as "elsewhere" and drop the link an unresolved base kept). Build-time `env!`/`option_env!`, a value rewritten by `.map(…)`/`format!`, a namesake module, a method called `var`, or a read nested as an argument state nothing. The data-source reader already renders the hole (`${env::var(…)…}/fixtures`) and core splits it into `baseExpr`.
- URL helpers ([url-helpers.ts](url-helpers.ts)): a client verb handed a URL helper the same file declares (`get(club_url(&self.base, id))`, the helper's body one `format!`) takes the helper's template with the arguments in place. A helper another file declares — a function whose whole body is one `format!` carries `FunctionInfo.urlTemplate`, parameters as `{name}` — is called through a `use` of its name (`club_url(id)`) or its module (`urls::club_url(id)`, only a module the file binds by `mod`/`use`): the target is the hole `${club_url(id)}` / `${urls.club_url(id)}`, which core's symbolic-target pass fills from the helper of the file the name stands for, never a namesake of another module.
- Request wrappers ([request-wrappers.ts](request-wrappers.ts)): a project method that hands its path parameter to a client (`self.request(Method::POST, path)`) is joined by core's `expandRequestFactories` from each call site's `pathArgCalls` — a literal, a `format!` or the caller's own path parameter, with the type it is called on (`self` is the `impl`'s type, a parameter its declared type, fields walked from there are `receiverFields`).
- Data: sqlx/raw SQL (multi-line `r#"…"#` raw strings are normalised to per-line fragments for the shared SQL scanner), Diesel tables, reqwest, env reads and lapin (AMQP) queues in [data-sources.ts](data-sources.ts); ORM entities for Diesel (`table!`, `joinable!`, `belongs_to`, `allow_tables_to_appear_in_same_query!`) and SeaORM (`#[sea_orm(table_name = …)]`, `DeriveEntityModel`, `Relation`) in [entities.ts](entities.ts) (+ [migration-files.ts](migration-files.ts)).

## Value flow (ANTLR reading only; the regex fallback states none)

[value-flow.ts](value-flow.ts): `let`/tuple patterns, `Some(Box::new(f))` wrappers, fields via `self`, `push`/`vec![…]`/`for … in`, `if let Some(cb)`, paren-called fields `(self.cb)(x)`, a `Self { cb: … }` literal as the receiver's fields (a `Self { … }` literal is stated only in a function taking no `self`), and a function's tail value. A `static` (uppercase name) a function stores into is stated at module scope (`moduleValueFlow`, with a self-`copy` marking the name bound).

## Taint

`regexTaint` (`{ gate, taint }`): a file whose source matches `gate` is parsed once more with `tree-sitter-rust` (shipped in `dist/grammars`, off with the `taint` feature) for the shared [handlerTaint](../shared/handler-taint.ts) walk — never a test or generated file or a tree with syntax errors. [taint.ts](taint.ts):

- A handler is a function with an axum/actix-web/rocket extractor parameter (`Query<T>`, `Json<T>`, `Path<T>`, `Form<T>`, `web::…`; a rocket route attribute's `<name>` segments; `HttpRequest` reads), or an `async` handler's `String`/`Bytes` last parameter beside another extractor — never `HeaderMap`, never a plain helper.
- Only what can hold text is tainted: a struct declared in the SAME file by its text fields, `String`/`&str`/paths; never numbers or booleans, never a type from another file (not judged).
- `format!` interpolation including `{name}` captures (`stringReads`); a comparison is a boolean and an `if`/`match` is its arms' values (`valueParts`); `.bind(x)` and `sqlx::query!` never fire.
- Measured: four reference Rust repositories with zero findings after the propagator, guard, free-text-parameter, `if`/`match` arm and rocket `PathBuf` rules were fixed — precision first.

## Tests, tooling and reachability

- Tests live beside the code: a `#[cfg(test)] mod tests` in the source file, cases carrying `#[test]` (or `#[tokio::test]`, `#[sqlx::test]`, `#[rstest]`, `#[test_case(…)]`); the file is no test file — a test attribute makes a case, any other function inside a `#[cfg(test)]` module is a helper (`testCase.kind` `helper`), never production code ([inline-tests.ts](inline-tests.ts)).
- [test-command.ts](test-command.ts): `cargo test -- <names>` (libtest takes several name filters after `--`, matched anywhere in a test's path); a marked test is named by its module path (`tests::finds_leader`) so an inline `#[cfg(test)]` case is told from a namesake elsewhere.
- `blockingCalls`: `std::thread::sleep`, `std::fs::…` inside an `isAsync` function.
- Dead code ([reachability.ts](reachability.ts)): the `mod` tree. A crate is built from its root (`src/main.rs`, `src/lib.rs`, `src/bin/*.rs`, `tests/*.rs`) by following `mod x;` (nested under inline modules as `mod:outer/name`) and `#[path = "…"]`/`include!("…")` (`path:<file>`, relative to the declaring file's directory); a `.rs` file no declaration reaches is not compiled. `use` never loads a file, so it resolves to nothing there (component-graph `use` edges still count, which only adds reachability).

## Layer 2 and control flow

- LSP: rust-analyzer (Docker image under `docker/rust/`; the asset is picked by `TARGETARCH`, `x86_64`/`aarch64-unknown-linux-gnu`; `readOnly` false because it writes `target/`; `indexDelayMs` 15 s — it needs significant warmup; a closing connection usually means it lacks `Cargo.toml` or a writable mount). Control flow is the approximate regex tier (`meta.regexControlFlow`).
- Symbols: tools write inline-module functions as `pitch::helper`; a lookup of `Garage::park` also finds `Garage.park` (`::` read as `.` when the written form names nothing).

## How core passes read it

- Field writes behind `borrow_mut()` / `lock().unwrap()` or a `*self.x` deref are writes of the field; a field receiver typed `std::io::Error` keeps its qualifier through `writtenTypeName` and binds a project class only where the project backs it (`qualifierBacksClass`). `crate` / `self` / `super` (`relativeTypeQualifiers`) name no module.
