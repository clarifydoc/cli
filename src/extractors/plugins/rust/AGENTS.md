# Rust plugin

Reads `.rs` files through a regex `RegexLangSpec` ([index.ts](index.ts)) with an ANTLR front end (`meta.antlr`, [antlr.ts](antlr.ts)) supplying functions and calls; a file with syntax errors keeps the regex reading. Parser internals (the SLL settling, lexer retyping) are in [parsers/AGENTS.md](../../../parsers/AGENTS.md). `#[...]` attributes ride the spec's `attributeLine`: an own-line attribute (`#[serde(rename = "x")]`) becomes a `decorators` entry on the item below it. LSP: rust-analyzer (Docker image under `docker/rust/`; asset picked by `TARGETARCH`; `readOnly` false because it writes `target/`; `indexDelayMs` 15 s; a closing connection usually means it lacks `Cargo.toml` or a writable mount). Control flow is the approximate regex tier (`meta.regexControlFlow`).

## Rules across files

- `importsNameDirectories`: a package import resolves to the directory the `packageDirectory` rule names. An import of a package a manifest declares or of the standard library never binds a project file by names. `importConfinement` confines a `crate::` path to the importing crate's own `src/`.
- Inline `mod` blocks: a function in an inline `mod pitch { fn helper() {} }` that shares its name with another function of the file is named by its module path (`pitch::helper`, `nameDuplicatesByModule`); one with no namesake keeps its bare name, since another file reaches it by that name through its `use`. A bare call inside a block is the block's own item, else the one item a glob of the block brings (`use super::*` in a `mod tests` nested in `mod pitch` is `pitch`'s), never the parent module's namesake. `pitch::helper()`, `self::`/`super::` and a `use … as` alias of an inline module resolve to the one function declared directly in that block (`inlineModuleMember`, run in the plugin's `postExtract`, both front ends alike). The manifest's `importedItemName` hook names the function an import path's inline modules give it. Tools write these as `pitch::helper`; a lookup of `Garage::park` also finds `Garage.park`. `postExtract` also states every inline block as `FileAnalysis.inlineModules` (name, `::` path, lines): core gives each plain function inside one its module path in its id (`pitch.run`, `pitch.inner.kick`, `tests.helper`), the names above untouched, so no link changes; a function already named `pitch::helper` is `pitch.helper`, and an impl method keeps `Car.name`. A lookup of `pitch::run`, `pitch.run` or `run` finds it.
- Crate and module names an importer writes: a manifest's `[lib] name` is a package name of its directory (`localPackages` in `package-manifests.ts`), and `use a::b::{self, C}` binds the module `b` too (`imports.ts`), so `league_lib::table::rank()` and `b::f()` link.
- Path calls: `pathCallTypesNeedScope` (`separator`, `selfTypes`, `typeSegment`): in `Garage::park()` the `CallInfo.receiverType` keeps the module path written before it (`crate::garage::Garage`), all three readers (ANTLR, ANTLR macro, regex) alike. The type binds only when the caller's file declares it, an import brings it in (named, alias, glob, a re-export or a `pub type X = path::X;` alias up to three hops) or the written path reaches it; a method of an `extension` part (an `impl` block in another file) is in scope when the type's declaration is; the link is labelled `class-name`, not `injection`.
  - A capitalized segment before the type (`Shape::Kind::make()`, `pathCallTypesNeedScope.typeSegment`) makes an associated-type path no import or module binds: left unlinked — unless the segment names a module file of the project (`mod Util;` in `Util.rs`, `namesModuleFile`), when it is a module and the type binds through it.
  - A written path to a free function of such a module (`crate::Util::tune()`, `capitalizedModuleCall`) is read as the lowercase spelling is (`target` the path, `member` the function, `moduleMember`) when no project type bears the name; a bare `Util::tune()` stays a type call. A path call through a project module (`util::format()`, not `std::`/`core::`/`alloc::`) is `keepNoise`.
- A `typesBeyondDirectory` language (Rust, Ruby): a type is looked up past its directory, the directory's declarations first; a qualified name or a name with several real declarations none of which the writing file owns refuses. `relativeTypeQualifiers` (`crate`/`self`/`super`) name no module, so `crate::Club` stays the project's own.
- Hierarchies: an `impl` block in another file or crate is `ClassInfo.extension` — a part of the type, never its declaration; a trait's default method is the ONE interface method the type (or one of its extension parts) implements. `transparentTypeWrappers` lists `Arc`/`Box`: `Arc<dyn T>` is `T`. A field receiver typed `std::io::Error` keeps its qualifier through `writtenTypeName` and binds a project class only where the project backs it (`qualifierBacksClass`).
- Struct literals construct: `Club { … }`, `league::Club { … }` become `construction: "literal"` calls through `withStructLiteralCalls` ([../shared/struct-literals.ts](../shared/struct-literals.ts)); never for a block opener (`impl Club {`, `if x {`) or a pattern (`Club { name } =>`). Alias `let q = p` / `&p` is `LocalType.aliasOf` ([../shared/alias-flow.ts](../shared/alias-flow.ts)).
- wasm bridge: a rule with `decorator.classes` (wasm-bindgen) also binds the classes carrying the attribute (`#[wasm_bindgen] struct`, `js_name` honoured) with their constructor and methods; the plugin hands an exporting `impl`'s attribute to each of its methods, and an `impl` in another file joins the struct's class; a multi-line `#[wasm_bindgen(…)]` on an `impl` reads like the one-line form.
- Route composition across files by route resolvers: axum `.nest("/api", api::routes())` and actix `.configure(routes::cfg)` whose callee lives in another file (`nest-resolver.ts`: per file the nests/configures with their scope prefix, the fn each route line is declared in and the `use` renames; chained, so a nest inside a nested fn composes); Rocket `mount("/api", …)` bases followed module by module through `routes![…]` lists, appended route functions and `pub use … as …` renames (`rocket-mounts.ts`; a base spelled `[basepath, "/api"].concat()` is its literal part).
- Data: sqlx/raw SQL (multi-line `r#"…"#` raw strings are normalised to per-line fragments for the shared SQL scanner), Diesel tables, reqwest, env reads and lapin (AMQP) queues in `data-sources.ts`; ORM entities for Diesel (`table!`, `joinable!`, `belongs_to`, `allow_tables_to_appear_in_same_query!`) and SeaORM (`#[sea_orm(table_name = …)]`, `DeriveEntityModel`, `Relation`) in `entities.ts`.
- Effects and flow: writes are read through `self.x`, `self.field.x`, `*self.x`, typed parameters and locals (details in `member-effects.ts`); a `Self { … }` literal states the receiver's fields in value flow only in a function taking no `self` (`value-flow.ts`).
- `blockingCalls`: `std::thread::sleep`, `std::fs::…` inside an `isAsync` function. `rust` has no `ast.taint` hook; the meta's `regexTaint` drives [taint.ts](taint.ts) through the shared [handlerTaint](../shared/handler-taint.ts) walk.
