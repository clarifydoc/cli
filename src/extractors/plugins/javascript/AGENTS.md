# JavaScript / TypeScript plugin

Reads JS/TS (`.js`, `.jsx`, `.mjs`, `.cjs`, `.ts`, `.tsx`), the script and template of Vue and Svelte single-file components, Astro pages, Angular components and templates, AngularJS, Alpine, Lightning Web Components, Aura controller JS and the Node/browser frameworks built on them. Front end: tree-sitter (TypeScript, TSX and JavaScript grammars; the `.tsx` variant is chosen per file; the script of a Vue/Svelte component is TypeScript text), read through flat trees (`FLAT_TREE_LANGUAGES` holds JavaScript and TypeScript). The plugin states facts; core resolves them ([core/symbol-linker.ts](../../../core/symbol-linker.ts), [core/value-flow.ts](../../../core/value-flow.ts), [core/route-linker.ts](../../../core/route-linker.ts)). Apex and the Aura/Visualforce markup belong to [../apex/AGENTS.md](../apex/AGENTS.md) and [../sfmarkup/AGENTS.md](../sfmarkup/AGENTS.md).

## Files and front end

- Entry points: [manifest.ts](manifest.ts) (static tier: extensions, markers, framework rules, package managers), [meta.ts](meta.ts) (lazy tier: hooks and extractors), [frameworks.ts](frameworks.ts) (`FrameworkRule[]`), [functions-classes.ts](functions-classes.ts), [imports-exports.ts](imports-exports.ts), [data-sources.ts](data-sources.ts), [data-mutations.ts](data-mutations.ts), [entities.ts](entities.ts), [routes/index.ts](routes/index.ts).
- Container formats: Vue SFCs are split by [../../../parsers/vue-sfc.ts](../../../parsers/vue-sfc.ts) into `<script>`, `<template>` and `<style>` blocks (`script`, `scriptLang`, `template`, `templateComponents`; template components are extracted separately by string matching), Svelte by [../../../parsers/svelte-sfc.ts](../../../parsers/svelte-sfc.ts), Astro by [../../../parsers/astro-sfc.ts](../../../parsers/astro-sfc.ts); the plugin's `preprocess` swaps in the embedded script. A built webpack/Parcel/browserify/esbuild bundle is refused by `preprocess` ([bundles.ts](bundles.ts)).
- A Vue template's expressions are parsed in place ([markup-expressions.ts](markup-expressions.ts)); markup calls are [markup-calls.ts](markup-calls.ts); handler text is cleaned per framework (Svelte `cleanHandler` in `parsers/svelte-sfc.ts`).
- A template statement that writes state is left as a comment naming only the cells it writes, never its text ([template-targets.ts](template-targets.ts), `withMarkupExpressions`).
- `v-for` loop variables are `FileAnalysis.templateLoops`, typed from the script and scoped to the element carrying the loop ([template-scopes.ts](template-scopes.ts)).
- Markdown pages are admitted only by the manifest's `pathScopedExtensions` gate ([markdown-pages.ts](markdown-pages.ts)); a README stays unread.
- Extension-less `#!` scripts whose interpreter the manifest's `shebangInterpreter` names are JS files. `platformSuffixes` (`.native`, `.ios`, `.android`, `.web`) lets `./Button` answer with `Button.ios.tsx` when no plain file exists; dead code keeps every variant alive.
- Import rewriting before call classification (shared, in `extractors/shared/`): tsconfig/jsconfig `paths` + `baseUrl` ([tsconfig-aliases.ts](../../shared/tsconfig-aliases.ts)), literal `resolve.alias` of `vite.config.*`/`webpack.config.*`/`vue.config.*` ([bundler-aliases.ts](../../shared/bundler-aliases.ts)), framework-generated aliases written only into a generated tsconfig (Nuxt `~`/`@`/`~~`/`@@`, SvelteKit `$lib` from `kit.files.lib`, else `src/lib`, and `kit.alias` entries whose bare paths are relative to the project root; one inside `node_modules` is left out), `${configDir}` in `extends`, and workspace packages npm/yarn/pnpm ([workspace-packages.ts](../../shared/workspace-packages.ts)).
- Framework auto-imports ([nuxt-auto-imports.ts](nuxt-auto-imports.ts)): in a sub-project with a `nuxt.config`, a `useX()` nothing imports and the file does not declare (never a framework built-in such as `useRoute`/`useState`) is read like an imported composable, the caller's own app first.
- Project passes: routes a build plugin generates from a page folder (unplugin-vue-router, vite-plugin-pages) and an Angular component's `templateUrl` template ([angular-external-templates.ts](angular-external-templates.ts)); `ast.fileRoutes` gives file-based routes (Next.js, Nuxt, SvelteKit, Astro, Expo Router, flat routes; [routes/file-based.ts](routes/file-based.ts), [routes/file-routes.ts](routes/file-routes.ts)).
- Packages: [package-manifests.ts](package-manifests.ts) is the npm `PackageManagerSpec` (`selfName` = package.json `name`, `workspace:` references resolved to the one sub-project declaring the package, `installedApi` reading `node_modules` declarations on demand, never during analysis — [installed-api.ts](installed-api.ts)); `**/package.json` is the sub-project marker; Node's built-ins ([node-builtins.ts](node-builtins.ts)) and any package a manifest declares never bind a project file by the names they import.
- Complexity and control flow are exact for TS/JS including Vue/Svelte SFCs. `securityInLiteral` drops a non-raw security rule's match that starts inside a quoted string or regex literal (never a template literal's text).
- Calls: noise names (`console.log`, `.map`, `.filter`, …) are filtered once in `NOISE_CALLS` of [../../shared/call-graph.ts](../../shared/call-graph.ts); `extractCalls` skips a childless node whose type it never reads unless the plugin lists the type as `perNodeTypes` (JSX, `return_statement`, `variable_declarator`, `assignment_expression`). A member chain written across lines is named as on one line (`compactCallName`).

## Structure: functions, classes, components

- `heldFunction` names a function expression no declarator names for where it is held (`<ClubEditDialog@saved@12>`, `<watch@21>`, `<Tag:prop@line>`…) and records the enclosing function handing it on ([held-functions.ts](held-functions.ts)).
- Call extraction hooks ([call-hooks.ts](call-hooks.ts)): `collectExtraCalls` (`passed` attribute/return/property values), `callbackArgNodeTypes` + `bindingSites`/`bindingPatterns` (an identifier argument is a call unless the function binds the name; per-site answer `boundAt`, [block-scope.ts](block-scope.ts)) and `statedMember`/`importedMapMember` (a noise-named member call kept when the file states the receiver is a project value).
- `this` of a nested method or plain function is not the component's; a watcher sharing a `methods`/`computed` name is `<watch@line>`.
- [functions-classes.ts](functions-classes.ts) also reads keyed registries (`extractKeyedRegistry`), ES5 prototype methods (`prototypeClasses`), a factory's returned members (`returnedMembers`, `returnedFrom`, `derivedLocals`), Vue `reactiveGetter` marks, `data()` member types (`typeDataMembers`) and parameter default callbacks (`ParamInfo.defaultCallback`).
- A gateway exported as a factory's result states `ExportInfo.factoryOf` ([imports-exports.ts](imports-exports.ts) `factoryResultOf`); the plugin never judges whether it is a factory, the linker's `exportedFactoryOf` step lands `Gateway.closeClub()` on the member (INFERRED `direct`). Such a factory's function members are functions of their own (`ClubApi.closeClub`) even beside values (`{ base, retries: 3, … }`), for an arrow or a function declaration (`functionObjectReturned(…, mixed)`); an exported factory whose result no module exports keeps the every-member-a-function rule.
- Doc comments come from [jsdoc.ts](jsdoc.ts) (a JSDoc `@throws {T}` is a `declared` thrown type beside the body's).

## Imports, exports and scope

- Default-import reference rows, re-export forms (`export { default as x } from`, `export * as ns`, a CommonJS barrel's `module.exports = { a, b }`) and lazy default exports (`lazyBinding`/`lazyDefaultOf`) are read in [imports-exports.ts](imports-exports.ts); they lead the linker to the definition.
- Import renames are `ImportInfo.aliases` (local → exported, `default` for a default import); the import index resolves through `resolveSpecifier`, never the local alias.
- A mixin that lists `mixins: [base]` puts the base's imports in scope too (`withMixinScope`, [vue-hooks.ts](vue-hooks.ts)); `ImportInfo.inScope.transitive` makes `inScopeMember` follow the chain.
- A JSX tag through a namespace import states `SubComponentInfo.namespaceMember`; the dispatch resolvers are wrapped by `seeingNamespaceTags` ([namespace-tags.ts](namespace-tags.ts)) so bindings, emits and `dispatch:renders` attach as for a named import; a member no export reaches stays unresolved, never a leaf-name guess.
- `import type` edges are `typeOnlyEdges` (cycles are judged without them). Processes JS starts (`fork`, `spawn`) are `executes` imports that share nothing ([../shared/process-spawns.ts](../shared/process-spawns.ts)).
- `inject()` holders and `provide(Key, useX())` + `inject(Key)` type the injected local by the same key ([provide-inject.ts](provide-inject.ts)).
- Vue global registration: `components.forEach((c) => Vue.component(c.name, c))` over an array of imported components registers each under the `name` option it declares (`SubComponentInfo.registeredByName`, `FileAnalysis.componentName`; `globalComponentFiles` reads the target's name, none declared is no tag) — [global-components.test.ts](global-components.test.ts).

## Linking rules: receivers, typing and dispatch

- Local typing facts: `localTypes` for typed locals, `from` for a local initialized by a call that states no type, `CallInfo.receiverType` for a lookup chained into a call. A destructured member read off a value or call result (`const { coach } = club.staff()`) is `localTypes[].member` with `from` = `club.staff().coach`, written only where the body calls on the name. `const [club, player] = load()` (and `await load()`) states each identifier as a local `from` the call with `fromIndex` (a hole counts; a rest/default/nested element states nothing); the manifest's `tupleElementsOf` ([tuple-elements.ts](tuple-elements.ts)) reads the declared `[Club, Player]` (`readonly`, labelled members; never an array, a rest or an optional member), through `Promise` when awaited.
- Conditional initializers: the plugin marks the arms of a ternary and of `let api; if (x) { api = a() } else { api = b() }` (one if/else-if/else chain or a `switch` with a `default`, directly after the declaration, every arm one plain assignment, the name touched nowhere else before the statement ends or is assigned again) with a shared `localTypes[].choice`, e.g. `const api = slug ? useGuestApi(slug).clubs : useLeagueApi()`; any other reassignment (assignments in separate `if`s, one after a call, a name read before the if/else) leaves the local untyped. Arms are all-or-nothing: the plugin emits every arm and never pre-filters.
- Alias flow ([variable-aliases.ts](variable-aliases.ts), `ast.variableAliases`): `const s = useStore()` then `s.x.y` is typed by the nearest binding before the alias, else untyped.
- Type tests narrow per call, never the name ([narrowing.ts](narrowing.ts)): `CallInfo.receiverType` is set only inside the region an `instanceof` guards.
- A name the nearest binder rebinds keeps no stale type: the parameter of a JS `this.x = function (p) {…}` states no handed argument (`handedArgs`) and no value-flow seed.
- Async results: the manifest's `asyncResultTypes` lists `Promise`, so a local bound to `await repo.find(1)` takes the type inside the `Promise<Club>` the callee declares; a loop over an awaited call takes the element of the result it unwraps.
- Calls the syntax hides: `calls.isApiCallShape(callName, imports)` marks tRPC `.query`/`.mutate` as an api-call whatever the receiver.
- Dispatch maps ([dispatch-maps.ts](dispatch-maps.ts), [dispatch-map-props.ts](dispatch-map-props.ts), [record-choice.ts](record-choice.ts)): a module-level map's values are `<setup>`'s and the linker joins `ACTIONS.save()` / `ACTIONS[kind]()` to them (INFERRED `dispatch:object-map`); a map handed down as a prop is `FunctionPropBinding.mapImport`; a record picked by a prop (`stores[props.kind]`, an IIFE or helper `switch`: `switchRecordEntries`) is narrowed by `recordChoice`, and never narrower than what one user could pick.
- A default-exported dispatch map and an array-pattern parameter ([function-values-default-array.test.ts](function-values-default-array.test.ts)): `export default { save: saveClub, remove, list: () => get() }` is a map held under the holder `default` (`defaultExportMap`; `call-hooks.ts` states a `property` call `default.<key>` per named value, and per key written in place unless the file declares a top-level name of that key, which is another function), and a default import handed down (`import actions from './clubActions'; <ClubRow actions={actions} />`, `defaultImportSource`) is a `mapImport` named `default` that the prop-callback resolver reads from the declaring module like a named one — a default export that is no map (data, a component's options) holds nothing, so nothing links. An array literal handed to a prop is one prop per position (`pair={[archive, purge]}` → `pair.0`, `pair.1`; a library object at a position → `pair.0.nextPage`, a dispatch map → `pair.0.<key>`; `elementHeldAt`), and a component taking `{ pair: [first, second] }` (`destructuredArrayProps` in `shared/destructuring.ts`; a hole keeps the positions, a rest or nested pattern binds nothing) calls the element at that position — the resolver's `arrayLocalOf` — while one taking `pair` whole does not. Not read: a Vue default import (`importedBindings` still excludes it), `const [a, b] = pair` in the body, an array pattern as the whole first parameter, a named map's keys written in place.
- Component props and callbacks: `JsPropCallbackResolver` (`dispatch:prop-callback`, [dispatch.ts](dispatch.ts); [prop-bindings.ts](prop-bindings.ts), [prop-flows.ts](prop-flows.ts), [vue-hooks.ts](vue-hooks.ts)) links a child's call of a callback prop to the handler each parent binds; a handler destructured from a hook that only reads a context (`useContext(Ctx)`) is the function of that name inside the provider component rendering `<Ctx.Provider>` in the hook's module (`contextMember`), and a props interface's method signature (`signaturesOf`) is no function: not one the child owns, and never a link's target (a wrapper forwarding its own prop follows it up to the grandparent's handler, or links nothing).
- Function props through arrays and JSX literals: `vueArrayFunctionProps`, `jsxPropElements` ([prop-bindings.ts](prop-bindings.ts)).
- Typed props and `JsParamTypeResolver` (`dispatch:param-type`): see [prop-flows.ts](prop-flows.ts).
- Emits: `declaredProps`/`declaredEmits` make component-emit → parent-handler EXTRACTED only when the child declares the event; dynamic emits and `<component :is>` fan out through [dispatch.ts](dispatch.ts), [dynamic-components.ts](dynamic-components.ts).
- A composable's options object is spelled in `CallInfo.args` by member ([call-hooks.ts](call-hooks.ts) `optionsArg`); core's `handedParameterLinks` reads it.
- Template refs ([template-refs.ts](template-refs.ts)): a ref's method call links to the child component's method.
- Library callbacks ([library-callbacks.ts](library-callbacks.ts), a knowledge table): a value a LIBRARY runs from the holder's method carries `CallInfo.libraryOption` (INFERRED `dispatch:library-option`); the table covers TanStack Table/Query and Formik.
- Scoped handlers ([scoped-handlers.ts](scoped-handlers.ts), `dispatch:scoped-handler`): a template handler under a component scope (AngularJS, Alpine) links to that component's member; the module side is [angularjs.ts](angularjs.ts), the by-name pass [dom-bindings.ts](dom-bindings.ts).
- Lightning Web Components: [lwc-template.ts](lwc-template.ts) links `onclick={handleSave}` to the class method, [apex-imports.ts](apex-imports.ts) the `@salesforce/apex/…` import to the Apex method (`foreignImportMember`); LWC files are passive reachability entries.
- Aura controller JS: [aura-controllers.ts](aura-controllers.ts); the joins are the markup plugin's `SfMarkupResolver` ([../sfmarkup/AGENTS.md](../sfmarkup/AGENTS.md)).
- Reactive cells and triggers ([reactive-cells.ts](reactive-cells.ts), [reactive-triggers.ts](reactive-triggers.ts), [core/reactive-triggers.ts](../../../core/reactive-triggers.ts), [signal-receivers.ts](signal-receivers.ts)): the plugin scopes each cell to the declaring component or class (`FileAnalysis.reactiveCells`); a write links the writer to the callbacks on the same cell (INFERRED `dispatch:reactive-trigger`).
- Angular subjects ([subject-flows.ts](subject-flows.ts), [subject-listens.ts](subject-listens.ts), [rxjs-subjects.ts](rxjs-subjects.ts), [component-subscriptions.ts](component-subscriptions.ts), `JsSubjectResolver`): `FileAnalysis.subjectFlows` links a `.next` to the listeners of the same subject (INFERRED `dispatch:subject`).
- Store state across files ([store-watch.ts](store-watch.ts), [store-reads.ts](store-reads.ts), `FileAnalysis.storeWatch`, `JsStoreWatchResolver`, `dispatch:store-watch`, INFERRED): watchers on a store's state join the writes of the store's actions and components, keyed by store file + class.
- DI: [di.ts](di.ts) and [di-bindings.ts](di-bindings.ts) state declared types as written, injection qualifiers (`@Inject(TOKEN)`), constructor parameters and container registrations as `FileAnalysis.diBindings`; core decides the implementation. Never pre-resolve here.

## Screens and navigation

- Every component file (JS/Vue/Svelte) is a screen of its own, composed by the screen-specs export; no `screen-navigation` pass is needed. The router outlet regexes (`routerOutlet`: `<RouterView|Outlet>`) mark layout screens ([routes/screen-tables.ts](routes/screen-tables.ts), [interactive-elements.ts](interactive-elements.ts), [sub-components.ts](sub-components.ts), [component-tree.ts](component-tree.ts), [element-types.ts](element-types.ts)).
- Navigation targets (`router.push`, `window.open`, `location`, `goto`, `routerLink`, `href`, `to=`) are read in [browser-navigations.ts](browser-navigations.ts) and the template readers.
- An Angular component's external template is part of its screen (links, outlet, rendered tags); a tag resolves through the plugin's `componentTags` (Angular selectors) ([angular-template.ts](angular-template.ts), [angular-listeners.test.ts](angular-listeners.test.ts)).
- A file-routed app (Nuxt `app.vue`, default layout — `appMount.routed`) is the entry of every page of its sub-project ([app-mounts.ts](app-mounts.ts)).
- Browser tests open pages by address (`page.goto`, `cy.visit`, `browser.url` → `FileAnalysis.browserNavigations`), joined to screens by core.
- A POST form with no action (HTML reader) marks `InteractiveElementInfo.ownViewPost`; a template expression in the attribute is a URL and never marks it.

## Member effects

- [member-effects.ts](member-effects.ts) states per function what it assigns (`FunctionInfo.fieldWrites`) and throws (`FunctionInfo.throws`); core resolves within the writer's language family by declared types only. It also states the property reads (`FunctionInfo.fieldReads`: `this.x`, a typed name's `x`, `this.field.x`; no callee, no plain `=` target, once per function and member); the Java/Kotlin reader ([member-effects.ts](java-kotlin/member-effects.ts)) does the same for `field_access` / `navigation_expression`.

## Reachability (dead code)

[reachability.ts](reachability.ts) is the reference model for `meta.reachability` and [path-references.ts](path-references.ts) its per-file half (glob imports, worker URLs, config-file script paths → `FileAnalysis.pathReferences`).

- Files and exports are judged; computed loads are path references, `bin/`, migrations and generator outputs are tool-loaded, framework directory conventions are gated on the framework id, and LWC/Aura bundles are passive ([reachability.ts](reachability.ts), [migration-files.ts](migration-files.ts)).

## Tests, taint and commands

- Taint: [taint.ts](taint.ts) is the plugin's `ast.taint` hook for the shared handler-taint walk ([../shared/handler-taint.ts](../shared/handler-taint.ts)).
- Tests: [test-cases.ts](test-cases.ts), [test-mocks.ts](test-mocks.ts), [test-command.ts](test-command.ts) (`testCommand`) and [project-commands.ts](project-commands.ts) (`projectCommands`: how the project is built, tested and started from its root files); a double anywhere on a call path hides everything below it from that test.

## Gotchas

- Plugins keep no module state: one process analyzes many projects.
- Do not add lazily-created cache properties to tree-sitter nodes; keep per-file data in `Map<node.id, value>` memos.
- A decoy is as important as a link: a namesake class, object, guard or constant of another file must never bind (see the "never a leaf-name guess" rules above).
- Bump `EXTRACTOR_VERSION` for any change in output for the same bytes.

## How core passes read it

- Symbol linker: `this.foo()` / `super.foo()` link on the enclosing class and its base; a call handed on as a value, `onClick={saveClub}`, is `passed`, and a name destructured from a factory's result takes `passed: "return"` with `CallInfo.returnedAs`. A function written in place and held (a watch callback, `<kit.action@4>`) is its own scope for local typing. A module declaring only `let ticket: SeasonTicket;` gets a `<setup>` pseudo-function.
- Channel factories: a wrapper `clientSend(event, room) { server.to(room).emit(event) }` publishes on the literal each call hands it (`DataSourceInfo.channelParameter`).
- Foreign bindings: a call through `as contracts` / `* as w`, a local bound to `await import(…)` or a module loader's awaited result, or `(await import("./pkg/club")).listClubs()` / `(await loadClub()).listClubs()` links to the function the generator rule binds; a decorated class joins through `new (await wasm()).SquadIndex()`, `index.search()` on a typed local or parameter, `this.index.search()`, `(await this.index).search()` and `Module.create()`.
- Screen navigation: `paths.app.club.getHref(id)` (a path table's member, resolved by its qualified name in its import's file), `navigate(…)`, `to={…}`, a nav item's `to:`, `{ name: 'clubs' }`, `ui-sref`, Ziggy `route()` and `route('clubs.show')` are named-route/path links; `.as()` names a route for redirects.
- Core's import resolution treats Node's built-ins (`path`, `fs`, `node:*`) as the standard library: no project file, and the names they bind are never matched to a project export.
- A class, interface or enum inside a TypeScript `namespace` states `ClassInfo.owner` (the namespace path, `Left` or `A.B`); core spells its id `Left.Builder`, and its members `Left.Builder.build`.
- A TypeScript `get x()` / `set x(v)` method states `FunctionInfo.accessor`; an overload signature is no function, so a name with one implementation keeps its id and a getter/setter pair is never two overloads.
