# C# plugin

Reads `.cs` and `.csx` (C# script) with tree-sitter (`tree-sitter-c-sharp`, flat-tree copy of the parse). Family `dotnet`: the VB, Blazor, XAML and F# plugins share its import-resolution family, and this plugin carries the .NET-wide pieces (the UI bridge, `.sln`/`.csproj` projects, NuGet, service config). See also [../vb/AGENTS.md](../vb/AGENTS.md), [../blazor/AGENTS.md](../blazor/AGENTS.md), [../xaml/AGENTS.md](../xaml/AGENTS.md), [../fsharp/AGENTS.md](../fsharp/AGENTS.md); cross-language mechanisms are in [../AGENTS.md](../AGENTS.md) and [../../../core/AGENTS.md](../../../core/AGENTS.md).

## Files and front end

- [manifest.ts](manifest.ts) (static tier): `parsing: "tree-sitter"`, extensions `.cs`/`.csx`, `family: "dotnet"`, `packageEcosystems: ["nuget"]`, `projectMarkers` `**/*.csproj` and `**/*.sln` (kind `dotnet`, priority 30; a .NET `.sln` adds nothing beyond them: each `ProjectReference` is already a `SubProject.references` entry), `dispatchLanguages: ["vb", "xaml"]` (the UI-bridge resolver joins VB and XAML code-behind too, so a pure-VB MAUI project must still load this plugin), `callPathsFromHead`, `linksFromBase` (Blazor code-behind `Nav.NavigateTo("orders")` and MAUI Shell `GoToAsync("Basket")` name app-root routes), `docComments: C_STYLE_DOCS`.
- Generated files: `*.Designer.cs`, `*.g.cs`, `*.g.i.cs` (case-sensitive, so a hand-written `ReportDesigner.cs` is not swept up). Test files: `…Test(s).cs` and anything in a .NET test project folder (`League.Core.Test/`, `League.Api.IntegrationTests/`); `testSubjectAffixes` `Tests`/`Test`.
- External-module prefixes `System`, `Microsoft.`, `Newtonsoft.`; framework import hints for `Microsoft.EntityFrameworkCore` (ef-core), `System.Data.Entity` (ef6), Dapper, NHibernate, RepoDb, PetaPoco. A `.csproj` alone means "some .NET project", not ASP.NET ([frameworks.ts](frameworks.ts)). A C# `Azure.` known-package rule never classifies a Python import (known-package tables answer by ecosystem).
- Extractors: [functions-classes.ts](functions-classes.ts), [imports-exports.ts](imports-exports.ts), [data-sources.ts](data-sources.ts), [entities.ts](entities.ts), [di-bindings.ts](di-bindings.ts), [dispatch.ts](dispatch.ts), [call-hooks.ts](call-hooks.ts), [local-types.ts](local-types.ts), [type-references.ts](type-references.ts), [member-effects.ts](member-effects.ts), [value-flow.ts](value-flow.ts), [routes/](routes/). [builtins.ts](builtins.ts) lists BCL/framework type names that are never project classes.
- `.csx` ([script.ts](script.ts)): the `#r`/`#load` directives — `#r "nuget: Dapper, 2.1.0"` / `#r "lib/Foo.dll"` and `#load "helpers.csx"` are turned into imports by the plugin's `preprocess` (the grammar wraps them in an ERROR node that can swallow the next line).
- C# 14 extension blocks ([extension-blocks.ts](extension-blocks.ts)): `extension(Car car) { … }` is read by the grammar as a constructor, so the header is rewritten before parsing into a nested class of the same length (lines and columns after it unchanged); after extraction its members move onto the enclosing class, each with the block's parameter as its receiver (`isReceiver`), as `static void Wash(this Car car)` has it.
- Visibility: C# methods default to package-private (`isExported = false` unless `public`).
- `extractCalls` does not enter a childless node whose type no step of its walk reads — 60% of a C# body's nodes (`READ_TYPES_BY_LANGUAGE`); a hook that acts on only some node types is gated on them before it reads text (Hangfire/`ToTable` arguments, `is`-pattern narrowing), and the per-call cost of the argument hooks ([arg-kinds.ts](arg-kinds.ts), [arg-origins.ts](arg-origins.ts)) is what is left of `extractCalls`.
- Flat tree: C# is in `FLAT_TREE_LANGUAGES`; a 4,000-file C# repository's cold CPU went 67.7 s → 43.5 s with identical output. In-process peak RSS is −20% on a 3,000-file C# repository under the bounded V8 heap growth (about +10% user CPU, equal wall time).

## Imports and scope

- `importsNamePackages: true` (a `using` names a namespace any file may declare), `nestedPackageLookup: true` (a type name is found in the file's namespace, each enclosing one, then its usings), `typesSpanFiles: true` (`partial` classes split one type across files, so a type's parts are one type), `bareMemberReceivers: true`.
- A file found by the name of its type (`using static Fx.Tools.Parts;` → `Parts.cs`) is the import's only when the namespace it declares is the one the source names (`importPath`, `nestedPackageLookup`): a namesake `Parts` of another namespace is never opened, and a qualified `Parts.Tune()` over classes of several namespaces takes the one the compiler's lookup (`nestedPackageFile`) decides, else no link.
- Extension methods: `extensionsNeedImport` keeps an extension method only where its declaring file is in the caller's scope — same file, the global namespace, a `using` of its namespace, its own or an enclosing namespace, a `global using`, an imported project, or `using static` of its class (`extensionInScope`, built on `importsFile`).
- Scope from the build ([package-manifests.ts](package-manifests.ts), `projectFileUsings`): `<ImplicitUsings>` puts the SDK's implicit global usings (base / Web / Worker / BlazorWebAssembly — the Blazor WebAssembly SDK adds only Configuration, DependencyInjection and Logging) plus `<Using Include>` minus `<Using Remove>` into `SubProject.implicitImports`, applied in MSBuild's evaluation order: SDK usings, then each `Directory.Build.props` up its `GetPathOfFileAbove` chain (the nearest one plus each parent it imports, outermost first), then the project body. A `<Using Remove>` takes away what came before it, so a Remove in the props and an Include in the project keeps the namespace (a conditional Remove still counts, a conditional Include does not). `<Using Include Static="true">` (`<Using Static="true">`) is a project-wide `using static` of that type.
- `using static`: the linker (`projectStaticScopes`) reads the project-wide statics and a `global using static` of any file as a scope every file of the sub-project has for bare calls, as a file-level `using static` is; an implicit import counts as a static only when it names a class of the project. A `using static` source is normalized (no spacing, no `global::`) and the linker names a nested static class through the classes whose lines enclose it before matching it (`League.Outer.Inner`).
- `extern alias`: the qualifier is the assembly, not part of the name. `using LeagueV1::Com.Example.League;` imports the namespace after `::`, and `LeagueV1::Com.Example.League.Club.Sign()` (or `LeagueV1::Ns.Club`) names the call without it (two assemblies declaring one namespace stay undistinguished). `global using Alias = …` is the only alias that reaches past its own file ([type-aliases.ts](type-aliases.ts)).
- A C# namespace is not a package directory for the function-type-alias scope walk (see Value flow).

## Linking rules

- Receivers: `bareMemberReceivers` makes a member win over a type of the same name — in `Color.Darken()` inside a class with a `Shade Color` property the head is the property (`Shade.Darken`), a same-file class `Color` takes no link; a member typed as the head itself (`Color Color`) leaves it to the type. A parameter or local of the caller's callable of another type or no stated one hides a class head too (`var Audio = factory.Make(); Audio.Click()` is no call on a project class `Audio`: `localHidesClassHead`; `Audio.Instance.Click()` with no such binding keeps the class).
- Explicit interface members (`void ICar.Start()`, `FunctionInfo.explicitInterface`) never take the class-qualified or bare name a same-named member of the class holds (`SymbolDef.explicitOnly`): a class-typed receiver reaches the public member, an interface-typed one the explicit implementation (`explicitImplementation`).
- Nested types: a call through a nested type's owner path (`Right.Builder.build()`) reaches the class nested in that owner, never a namesake nested elsewhere; where no class is nested in the head's own lines, the one `ownerPathType` finds (a generated class's `nestedPath`, a nested type the owner inherits through its bases) is used.
- Overloads are chosen by argument kind (`CallInfo.argKinds`, `calls.argKindsOf` / `overloadTypeKey`; [arg-kinds.ts](arg-kinds.ts)), by arity only when kinds are unknown. `Foo x = new();` (target-typed construction) names its class only in the declaration ([call-hooks.ts](call-hooks.ts)).
- Type-parameter bounds ([type-bounds.ts](type-bounds.ts)): `M<U>(U u) where U : Boat` and class-level `where T : Car` give each parameter and typed local written as that bare letter the bound as its type (core is untouched). A method's own letter beats the class's; with several bounds the FIRST is taken, skipping `class`/`struct`/`new()`/`notnull`/`unmanaged` (`where T : class, Boat` takes `Boat`) — the plugin cannot tell a project class from a library interface, so a project class listed after a library bound is missed; `where T : U` leaves the letter untyped; fields and constructor properties written as the letter, and a local class or lambda inside a generic method, are not covered.
- Type tests ([type-tests.ts](type-tests.ts)): `if (x is Club) { x.Sign(); }` (also `is not`) narrows PER CALL — `CallInfo.receiverType` is set only on calls inside the region the test guards; a call outside it, in a callback body or after the name is reassigned gets none.
- Tuples ([tuple-elements.ts](tuple-elements.ts)): `var (club, player) = Load()` and `(var club, var player) = Load()` over `(Club, Player)`, `(Club club, Player player)` or `ValueTuple<…>`, awaited through `Task`, are `fromIndex` locals typed by the manifest's `tupleElementsOf`; a class with its own `Deconstruct` states nothing; a discard or nested pattern only takes up a position.
- Element bindings ([element-types.ts](element-types.ts)): a loop, LINQ / `ForEach` callback, `catch` or element read states a `localTypes` entry whose `from` names what it is drawn from; JVM and .NET share the chain reader in `shared/element-chain.ts`. Two element types for one name leave it untyped.
- Unwrapping: the manifest's `asyncResultTypes: ["Task", "ValueTask"]` unwraps `Task<T>` (a local bound to `await repo.FindAsync(id)` takes the type inside the declared `Task<User>`). `valueOut` members: `.Value` on `Lazy<T>` / `IOptions<T>` / `IOptionsSnapshot<T>` and `CurrentValue` on `IOptionsMonitor<T>` read a head, field or method result that DECLARES a listed wrapper (`_options.Value.Reload()`, read by `unwrappedDeclared`/`wrappedHead` in `core/symbol-linker.ts` from the written type); a project class's own `Value` property is not unwrapped (a wrapper whose members are its own is not listed). A local holding the unwrapped value (`var s = _options.Value; s.Reload()`) is stated as `localTypes[].from = "_options.Value"` with `member: true` — the plugin states EVERY plain member-read initializer (`var m = club.Boss`) and core decides (a listed wrapper unwraps, else the member's declared type).
- Conditional initializers `c ? a() : b()` mark their arms with `localTypes[].choice`; a C# local assigned on each arm (`var api; if … {…} else {…}`) is typed by its declared type; `collectionElementOf` reads the element of a declared collection for a loop variable.
- LINQ predicates (`.Where(c => c.Id == id)`) count as column filters for the route-parameter → column pass (`paramColumns`).
- UI bridge ([ui-bridge.ts](ui-bridge.ts), `CsharpUiBridgeResolver`): joins what the generic linker cannot see, by CLASS NAME (several classes of one name — two app versions vendored in one repo — the candidate whose path shares the longest prefix with the UI file wins), as INFERRED `<ui file>::<site> → <cs file>::<Class>.<handler>` links: (1) WinForms partial classes — the wiring `MnuOpenFile.Click += MnuOpenFile_Click;` sits in `FrmMain.Designer.cs`, the handler in another partial file; (2) XAML code-behind — `Click="ButtonCopy_Click"` in `Foo.axaml` names a method of the `x:Class` class, implemented in `Foo.axaml.cs`; (3) Blazor code-behind — `@onclick="Save"` in `Garage.razor` names a method of the component class, a partial whose code sits in `Garage.razor.cs` when the markup's own `@code` block does not declare it. The partial-class join is language-agnostic, which is why VB and XAML code-behind reach it.
- WinForms UI ([winforms-ui.ts](winforms-ui.ts)): event subscriptions (`MnuOpenFile.Click += MnuOpenFile_Click;`, legacy `this.button1.Click += new System.EventHandler(this.button1_Click);`) in `*.Designer.cs` `InitializeComponent()` and in hand-wired form code — it runs on every C# file and gates on the event name, not the file name — and the Designer file as a full form description (control declarations, `Controls.Add(…)` containment, `DropDownItems.AddRange(…)`, `Text = "…"` captions, geometry): one `ScreenInfo` per form.
- Commands ([command-handlers.ts](command-handlers.ts)): `KeepCommand = new RelayCommand(Keep)` (constructor, initializer or expression-bodied property; `DelegateCommand`, `AsyncRelayCommand`, `ReactiveCommand`, and the lambda forms `() => Keep()` / `async () => await Keep()`) makes the command property run `Keep`. Only a command built over one method of the class is recorded; a lambda body with other statements, or one assigned twice to different methods, names nothing.
- CommunityToolkit `[ObservableProperty]` on a field gives the class its generated public property, typed as the field (`_clubName` → `ClubName`, marked `accessor`/generated).

## Dependency injection and registration scans

- Plugins report facts, core decides ([di-bindings.ts](di-bindings.ts), `meta.ast.diBindings`): container registrations; `[FromKeyedServices("k")]` is an injection point's `qualifier`; `TryAdd*` is `ifAbsent`.
- Registration by scan ([assembly-scan.ts](assembly-scan.ts)): each `AddMediatR(…RegisterServicesFromAssembly(typeof(X).Assembly))` / `AddMediator()` / MassTransit `AddConsumers…` / `new EndpointConfiguration(…)` (NServiceBus) is a `cs:assembly-scan` route fact (markers = the `typeof`/generic types named; none = the registering project). `CSharpAssemblyScanResolver` links the registering function (else `<setup>`) to the `Handle`/`Consume` of every class implementing the family's handler interface in the project that declares the marker (the registering project's namesake first; `Program` with top-level statements is the registering project; a marker nothing declares scans nothing).
- MediatR ([dispatch.ts](dispatch.ts)): indexes every `IRequestHandler<T>` / `INotificationHandler<T>` / `IStreamRequestHandler<T>` by request type `T`; each callable that dispatches through a mediator (`_mediator.Send(new GetOwnersQuery(…))`) gets a synthetic `caller → Handler.Handle` link for every request type it constructs (`new T(…)`) or forwards as a parameter (`Send(command)`).
- Hangfire jobs run by id: `RecurringJob.TriggerJob(id)` / `IRecurringJobManager.Trigger(id)` name no method; [hangfire-triggers.ts](hangfire-triggers.ts) states the arguments of the trigger and of the `AddOrUpdate` registration it names (`CallInfo.args`, through `meta.calls.argsOf`) and its dispatch resolver links the triggering function to the method the registration's lambda runs — on the one class implementing the registered interface (two or more refuse, so a decoy is never linked), or the registered class, or the registering class for a bare `() => Sweep()`. An id is a string literal or a `const` the named (else the caller's own, else the one project) class declares in `ClassInfo.fieldValues`; an unreadable id, or one two registrations give different handlers, links nothing. The scheduled-job entry-point reader ([scheduled-jobs.ts](scheduled-jobs.ts)) accepts the same id shapes on `AddOrUpdate` — a string literal, `nameof(…)`, a bare identifier, or a `Class.Const` — and resolves a same-file `const string Leaf = "…"` to that literal when the file declares it once.

## Value flow

[value-flow.ts](value-flow.ts) states `ValueFlowFact`s per member (core's solver is in [../../../core/AGENTS.md](../../../core/AGENTS.md)):

- A method group (`Action a = Save`, `new Action(this.Load)`, `Run(Save)`, `club.Count` where the destination is a delegate), a delegate in a local, parameter, field or property, `x()` / `x.Invoke()` / `x?.Invoke()`, a delegate returned by a factory (`Task<…>` unwrapped), and collections of handlers (a literal key is its own cell and `[]` too; a field collection is one cell). An element call with no call row (`handlers[key]()`) is the invoke's `handlers[]`.
- Events: `r.Saved += OnSaved` stores into the declaring class's cell and the raise inside it invokes it; the plugin lists a class's events in `ClassInfo.events` (they are no properties), so a subscription through a derived type lands in the base class's cell, and one through an interface that declares the event too reaches the implementer's raise (`fieldCell` copies the interface's cell into the declarer's, one way, never between two implementers).
- A name is a delegate holder by its declared type (BCL delegates and the file's own `delegate` declarations; `x()` on a declared local, parameter or own field is always a delegate call). A field, parameter or local typed by a plain name it calls (`_onSigned(c)`, `Signed?.Invoke(c)`) is an `invoke` with `ifFnType`; `delegate` declarations are `FileAnalysis.functionTypeAliases` (the `ast.functionTypeAliases` hook). Core keeps the invoke only when the nearest scope declaring that name — file, imports, own sub-project, imported sub-projects, then the projects its build references (`SubProject.references`, no import line needed) — declares a function-type alias and no class of it; a plain-typed parameter only handed on as an argument keeps its flow (it is the cell the callee's formal joins).
- A field's delegate initializer is stated on the class's first constructor. A lambda or anonymous method in a local, field, property, event `+=`, collection, argument, return or field initializer stands for the project functions its body calls (`Save()`, `this.Save()`, `club.Save()`, `Club.Save()`; at most four project functions, counted by core over the `lambda` id its facts share; none for a call on its own parameter or a chain; a BCL call is filtered by name where it can be) and copies the delegate it runs (`onDone()`, `onDone.Invoke()`), having no function of its own.
- Top-level statements (`Program.cs`) are `moduleValueFlow` on `<setup>`, a bare name there being a method group only for a top-level local function.
- A named argument (`Schedule(callback: F)`) is an `arg` with `name`, never mapped by position; C# keeps its argument loop (a type has no namespace in the call, so a library receiver cannot be told from a project one).

## Routes and frameworks

- ASP.NET attribute routing ([routes/aspnet.ts](routes/aspnet.ts), the reference route extractor with `java-kotlin/routes/meta-annotations.ts`): class-level attributes are inherited by every action, an anonymous marker waives (`[AllowAnonymous]`), `[MapToApiVersion]` narrows, a binding derived from framework defaults is `inferred: true`. Decorators keep their arguments (`Authorize(Policy = nameof(X))`, `ApiVersion("2", Deprecated = true)`).
- `Name =` on a verb attribute, or the `[Route]` beside it, is `RouteInfo.name` (what `CreatedAtRoute` / `Url.RouteUrl` / `RedirectToRoute` name); a `Name =` alone is never the path. `[controller]` / `[action]` tokens expand for the controller that serves the action — on an action inherited from a base, the subclass's token, from the raw `name` on the `cs:controller` action fact — never the declaring base's.
- [routes/aspnet-resolver.ts](routes/aspnet-resolver.ts): base-controller `[Route]`/`[ApiController]`/`[Authorize]` inheritance and abstract base actions served by each subclass. [routes/aspnet-attributes.ts](routes/aspnet-attributes.ts): a project's own routing attributes (`[V3ApiController]` implementing `IRouteTemplateProvider`, `[RestPutById] : HttpPutAttribute`) are recorded per file as a small expression IR (`cs:attr-def` facts — constructor params + defaults, `base(…)` args, `Template`/`HttpMethods` values, consts) and evaluated at each use site through the constructor chain; a template no evaluation can state marks the rows `prefixUnresolved: "attribute:X"`, and a verb attribute with such a template routes nothing.
- Conventional routing ([routes/aspnet-conventional.ts](routes/aspnet-conventional.ts)): the route tables a startup file registers (`MapControllerRoute`, MVC 5 `MapRoute`, Web API 2 `MapHttpRoute`) are applied to controllers no attribute routes.
- Filters: `[ServiceFilter(typeof(X))]` / `[TypeFilter(typeof(X))]` on controllers and Razor `PageModel` classes land in `RouteInfo.filters` and name the filter type's pipeline entry in `middlewareCalls` — `OnAuthorizationAsync` / `OnAuthorization` when the type name says Authorization, otherwise action-filter methods ([routes/filter-middleware.ts](routes/filter-middleware.ts); class-level filters on a page model reach every handler in [routes/razor-pages.ts](routes/razor-pages.ts)).
- Razor Pages: `Pages/Club.cshtml` declares `@page "/clubs/{id:int}"` and its code-behind handlers are the routes ([routes/razor-pages.ts](routes/razor-pages.ts)).
- Minimal APIs ([routes/minimal-api.ts](routes/minimal-api.ts), [routes/minimal-api-resolver.ts](routes/minimal-api-resolver.ts)): guards declared where a group is used (a group method's caller), not where it is built.
- Azure Functions HTTP triggers (isolated worker `[Function("GetKit")]` and in-process): [routes/azure-functions.ts](routes/azure-functions.ts). FastEndpoints (`Endpoint<TReq, TRes>` classes, group and global prefixes no endpoint file states): [routes/fast-endpoints.ts](routes/fast-endpoints.ts), [routes/fast-endpoint-prefixes.ts](routes/fast-endpoint-prefixes.ts).
- HotChocolate code-first schemas ([graphql.ts](graphql.ts)): root fields `POST /graphql/<field>`; a root class is one registered as a root type (`AddQueryType<T>()`, facts collected per file), one whose attribute says so (`[QueryType]`, `[ExtendObjectType("Query")]`, `OperationTypeNames.Mutation`, `typeof(Mutation)`), or one named Query/Mutation/Subscription in a file using HotChocolate. Each public method or property is a field named as HotChocolate names it (`Get` and `Async` dropped, camelCased) unless `[GraphQLName("x")]`; arguments are its parameters minus what the server injects (a registered type, a `DbContext`, a repository, a `CancellationToken`, the resolver context); `[Authorize]` is its guard.
- Request schemas ([request-schema.ts](request-schema.ts), `meta.requestSchema`: `unwrapNullable`, `describeType`, `serializedName`, `isSerialized`, `isRequired`): how types and properties look on the wire under System.Text.Json; the core pass does class lookup, inheritance flattening and recursion. `camelCase` (shared `inflection.ts`) is the JSON name .NET serializers give a property (C#, VB).
- Taint ([taint.ts](taint.ts)): an action is a method with an HTTP verb or `[Route]` attribute; parameters are bound from the request (`[FromQuery]`/`[FromRoute]`/`[FromBody]`/`[FromForm]`/`[FromHeader]`, or unannotated) except what the container injects (`[FromServices]`, services, contexts, loggers, cancellation tokens); `Request.Query[…]`, `Request.Form[…]` are request input; `$"…{name}…"` carries `name`, a literal's text does not.

## API calls and service config

- HTTP clients ([http-clients.ts](http-clients.ts)): `IHttpClientFactory` — typed (`AddHttpClient<InventoryClient>(c => c.BaseAddress = …)`; `AddHttpClient<IInventory, InventoryClient>` is the implementation, where the HttpClient lands) and named (`AddHttpClient("legacy", …)` reached through `factory.CreateClient("legacy")` → `name:legacy`); a class that sets its own client's base (`_http.BaseAddress = …`, `new HttpClient { BaseAddress = … }`) registers under the class name too. Only facts are reported; core's call-origin pass matches calls to them.
- Refit ([refit.ts](refit.ts)): `AddRefitClient<IClubApi>()` / `RestService.For<IClubApi>(…)` is keyed by the API interface whose verb-attributed methods are the requests (`[Get("/{id}")]`); each row's target starts with the client as an unknown base (`${IClubApi}/{id}`) which core replaces with the registration's address and which, unregistered, keeps the path from passing for a whole one. A generated proxy of an API interface sets `proxyOf` to its fully qualified name, and core turns every call on a receiver of that type into a contract call.
- Request and response shapes: [request-body.ts](request-body.ts) reads the body a `PostAsJsonAsync` / `PutAsJsonAsync` / `PatchAsJsonAsync` call sends (anonymous object, object initializer, or a local holding one; web defaults, so `Name` goes as `name`; values typed by their literal, anything else an empty schema, null when the body is not stated); [response-reads.ts](response-reads.ts) reads the top-level fields a caller reads off a JSON response (`GetFromJsonAsync<OrderDto>` then `order.Total`, `ReadFromJsonAsync<OrderDto>`), camelCased, a method called on the value being no field; [arg-origins.ts](arg-origins.ts) states where a call's arguments come from (`CallInfo.argOrigins`) for the pass that follows a route parameter to the column a query filters on — a parameter of the enclosing member, a request value (`Request.Query["q"]`, `RouteData.Values["id"]`), a string literal; one conversion is unwrapped (`int.Parse(id)`, `(long)id`).
- Service config ([service-config.ts](service-config.ts)): `appsettings*.json` and launchSettings, `IConfiguration[...]` / `_config["A:B"]` bases, `__` env overrides, the `ReverseProxy` section (YARP, forwarding rules) and `ocelot.json`; [forwarders.ts](forwarders.ts) reads YARP's in-code `app.MapForwarder("/api/v2/cars/{**catch-all}", "http://cars:8080")` (every request under the pattern's literal prefix goes to the destination, path kept; a following transform builder is not read). [aspire.ts](aspire.ts): a .NET Aspire AppHost (`DistributedApplication.CreateBuilder(args)`) is an address book — every resource it adds (`AddProject<Projects.League_Api>("api")`, `AddNpmApp`, `AddPostgres("pg").AddDatabase("leaguedb")`, `AddRedis`, `AddRabbitMQ`) under the name service discovery gives it (`https+http://api`), the project it runs, and the `.WithReference(…)` edges.
- MQTT (`DataSourceInfo.topicSyntax: "mqtt"`, MQTTnet) and topic names held in constants: a topic argument that is a `Type.Name` constant of a project module, or a `Class.member` of this file, is a row with `target: null` + `targetRef` which core's module-value pass fills from the declaring class. Dapr pub/sub (the C# SDK, each file gated on importing it) keys a publish and a subscription by topic.
- A call through a registered client carries `baseRef: { kind: "client" }` (or `client`).

## Data access and entities

- [data-sources.ts](data-sources.ts) surfaces Entity Framework, Dapper, NHibernate, RepoDb and PetaPoco accesses and SQL strings (through the shared SQL-string reader); [entities.ts](entities.ts) is the EF Core (and lightly NHibernate) entity extractor; its project pass uses the shared `repository-access` helper for repositories over a generic base. Migrations: [migration-files.ts](migration-files.ts) (`Migrations/<timestamp>_<Name>.cs`).
- Query helpers: a method declared to return `IQueryable<T>` (ordered / including forms, `DbSet<T>`, or a task of one) is a read where it is built; a chain that STARTS at a call of one declared in the same class — `ClubsQuery(id).ExecuteDeleteAsync()`, `this.Active().ExecuteUpdateAsync(…)`, `var q = ClubsQuery(id); q.ExecuteDelete()` — is the read or write it names on the set the helper queries (read off its returned expression, else its declared `T`), at the caller (`queryHelperEntity`). A same-named helper of another class is not followed.
- A bulk write on a query ANOTHER class's method returns (`_repo.Active().ExecuteUpdateAsync(…)`, through nothing but query composition — `Where`, `AsNoTracking`, `Include`… — with the receiver a field, property or parameter of a declared class) is a write row stating `DataSourceInfo.entityProducer` (`{ type: "ClubRepository", method: "Active" }`, no entity); the entity extractor's project pass (`producedQueryEntities`) types it by that method's declared `IQueryable<Club>` (or `DbSet`, or a task of one) when every class of that name declaring the method agrees, so a same-named helper of another class, a method returning no query and a type parameter bind nothing. A bulk write (`ExecuteUpdateAsync`/`ExecuteDeleteAsync`) on a query whose producing method yields no entity is dropped rather than kept as a row with no table.
- A project anchored only by a migration or a `DbContext` would have every other file reported dead, so those are passive, never entries.

## Member effects

[member-effects.ts](member-effects.ts) states `FunctionInfo.fieldWrites` / `throws` (assignments, thrown types) for core's `member-effects` pass. Types are resolved to project classes by declared types only and only within the language family; C# types found only in the writer's directory (`typesSpanFiles` without `typesBeyondDirectory`) are looked up as written; a qualified name binds by its last segment only through a qualifier the project backs (a namespace the class is declared in — `ClassInfo.namespace` — or a name the writing file imports, `using Err = …`).

## Reachability and entry points

[reachability.ts](reachability.ts): a `using` names a namespace, never a file, so types are found by NAME across the assembly (`declaredNames`) — a file is reached when reachable code mentions a type it declares. A program starts at `Program.cs` / `Main`; what ASP.NET, the generic host, MediatR, EF, FluentValidation, AutoMapper, SignalR, WinForms/WPF/MAUI and test runners discover by attribute or base type (`[ApiController]`s, assembly scanning) is kept alive and never reported but anchors nothing (`passiveReason`) — a class library full of controllers is still a library. `configMentions` (appsettings and the like) anchor what the framework instantiates by name. An import graph cannot prove C# files unreachable, hence the name-based model.

## Tests, commands, performance patterns

- `testCommand` ([test-command.ts](test-command.ts)): `dotnet test --filter …`; `projectCommands` ([project-commands.ts](project-commands.ts)) reads how a project is built, tested and started.
- `blockingCalls` (matched by name inside an `isAsync` function): `Thread.Sleep`, `….GetAwaiter().GetResult`, `Task.WaitAll`/`WaitAny`; `.Wait()` and `.Result` are not listed (a project class may carry them). `blockingOnReceiver` (`{ receiverTypes, members, types }`: `Wait` on `Task`/`ValueTask`) flags `receiver.member()` in an async function when the receiver's declared type matches — a parameter, a local's stated type, a field of the caller's class, or the declared return of the call it was initialized from (`own()`, `field.method()` through a class the project declares once; `repo.SaveAsync().Wait()` is typed by `SaveAsync`'s declared return); an unknown type, a project class named like the type, or a sync method flags nothing. `.Result` is a property read no call states: with `readMembers` (`Result`) the plugin states `FunctionInfo.propertyReads` ([property-reads.ts](property-reads.ts): a name, `this.field` or a call chain as receiver, only in an async method, never inside a lambda or local function, never a name the body awaits); the property-read edge is not built, the reads feed only the blocking-call rule.
