# C++ plugin

Reads C++ (`.h`, `.hpp`, `.hxx`, `.hh`, `.cpp`, `.cc`, `.cxx`, CUDA `.cu`/`.cuh`) through a regex spec plus an ANTLR front end (`antlr.ts`, `meta.antlr`); a file with syntax errors keeps the regex reading (`FileAnalysis.frontEnd`; `--feature no-antlr` switches to regex). It also owns the facts C, C++ and Objective-C share (the `cfam` family), the QML plugin (`../qml/`) and the Qt Designer plugin (`../qtui/`). The C plugin ([../c/AGENTS.md](../c/AGENTS.md)) and Objective-C plugin ([../objc/AGENTS.md](../objc/AGENTS.md)) link here. Parser internals (decision settling, the `CTypes`/`CppTypes` passes, grammar regeneration, `.h` variant reading) are in [../../../parsers/AGENTS.md](../../../parsers/AGENTS.md) and not repeated.

## Files

- `manifest.ts` — static tier: include scope, compilation database, overload ranking, `.h` reading variant (`readingVariant`), vendored banners; the scope rules are documented there.
- `index.ts` — the regex `RegexLangSpec` (patterns, `declarationCallPatterns`, direct-init and field-path calls); `meta.ts` wires it.
- `antlr.ts` — the ANTLR front end: calls, locals, operators, iterators, maps, structured bindings, Qt string connects, callable fields.
- `classes.ts` — class, namespace, one-line-class and template-head reading; `collection-element.ts` — container/map/pair element types; `arg-kinds.ts` — declared type → overload key. A built-in local (`int shirt`, `const char* tag`) has no `localTypes` entry, so `antlr.ts` (`builtinKind`) writes its overload key onto the call's `argKinds` when the function declares the name once, as a local; `typed-local-overload.test.ts` pins it.
- `member-effects.ts` — field writes and throws; `qt-slots.ts`, `connect-elements.ts` — Qt connect reading; `project-markers.ts` — CMake `project()` root check; `frameworks.ts` (rule `qt`), `package-manifests.ts`, `packages.ts` — vcpkg/conan.

## Cross-file rules

- `.h` is shared between C and C++ and has one owner (C++). `readingVariant` gets the project's file counts by extension and names `c-first` for a `.h` in a project with `.c` and no C++ source (`.mm` counts as C++); the analyzer folds the variant into the manifest `resolver` stamp, so a project whose mix flips re-reads its headers; `FileAnalysis.frontEnd.variant` records it. A header whose C++ is only inside `#ifdef __cplusplus` is offered to the C reader (`withoutCppGuards`).
- [../shared/brace-code.ts](../shared/brace-code.ts) (`BraceLexicon`, `braceCodeHooks`) and [../shared/c-family-code.ts](../shared/c-family-code.ts) count braces over code only and say when a signature is a definition; Go, Rust, Scala and Swift use the brace helper too. The control-flow `sourceView` is `firstBranchView` ([../shared/preprocessor-branches.ts](../shared/preprocessor-branches.ts)).
- A parser states the class a member is declared in (`ParsedFunctionSpan.owner`); `adoptParsedMembers` adopts by that name even on the class's own line (`struct A { auto f() -> int { return 1; } };` is `A.f`, never a free function a bare `f()` could bind to) when exactly one class of that name covers the span, and refuses when several share the extent.
- A C++ namespace/class/template rule lives in `classes.ts`; an include or overload rule in `manifest.ts`; a receiver rule in `antlr.ts`. Start there, not here.
- `LocalType.aliasOf`: `auto& q = p` / `= *p` is `type: ""` + `aliasOf: "p"`, emitted only when the name is bound once from one head and never reassigned (never `nullptr`/`this`); flow order is read by [../shared/alias-flow.ts](../shared/alias-flow.ts): a loop or closure around the alias, or a binding in a block that closed before it, leaves it untyped. A block-local `using X = T;` / `typedef` types that block's locals.
- Aliases: a pointer or reference alias (`using ClubRef = Club*;`) is a `typeAliases` entry for the pointee (`pointeeOf` in [../shared/c-family-aliases.ts](../shared/c-family-aliases.ts); `Club**` stays untyped), so `ClubRef c; c->play()` types like `Club* c`. A namespace alias (`namespace lib = home;`) is the same table: the linker rewrites a qualifier through it before matching `ClassInfo.namespace`; a foreign namespace with no alias refuses rather than falling to a bare namesake. The scanner reads `typedef`s inside `extern "C"`.
- Callable fields (`PropertyInfo.callable`): a call `x.m()` / `this->m()` through one is derived by core (`fieldInvokes`, no plugin fact) when the receiver's class, found by `locateClass` through the include closure then its bases, declares `m` callable. A positional aggregate initializer `T t{ a, b }` and a typedef in another file are not read by this path.
- A positional initializer (`static struct club_ops ops = { "club", 0, club_scout };`) seeds the fields it fills (`ValueCell.positional`): each element that is a function of the file is a seed on `{ name: <struct type>, member: "#N", positional: { index, count } }`. Core names the field in `cellOf` from the property at `index` of the class `classOfType` finds (`locateClass` through the include closure, then `dealias`, then the one declaration with a body), refusing when the class is unknown, ambiguous, not `fieldOrder` or has fewer fields than elements. The plugin refuses an initializer that mixes designators or has a bare upper-case name or call the file does not define (a macro may widen).
- Value flow is read by [../shared/c-family-value-flow.ts](../shared/c-family-value-flow.ts) (the spec's `extractValueFlow` on the finished analysis), statement by statement: function pointers, `std::function`, lambdas/`std::bind` held in locals, fields (set in a method or a constructor's initializer list, run in another), file-scope globals (`module: true`), arrays/vectors of handlers (one cell), and struct ops tables (`{ .sign = club_sign }` seeds the struct TYPE's member; nested tables are a field path, `club_conf.ops`). A lambda stands for the project functions its body calls (up to 16 stated, four counted by core, one `lambda` id). A function writing a global it does not declare states `{ name: X, module: true }`. A member call is an `invoke` in C always, in C++ only for a member the file stores a callable in. A cell name that is no binding but a project class names that class's members; a dotted name walks property types first.
- A name typed by a plain identifier the file cannot judge (a typedef in another file) states its `invoke` with `ifFnType`; the file lists its own function-type aliases in `functionTypeAliases`. Core keeps the invoke (host `isFunctionType`) only when the name, as seen from the file's whole include closure, is an alias and no class (one pool across `.c` and the `.h` read as C++; class only or both = a class; never pooled across sub-projects). A dropped invoke neither links nor keeps the name tiers off the call. C-specific emission rules: [../c/AGENTS.md](../c/AGENTS.md).

## Reading details by file

- `antlr.ts` also names `p->m()` like `x.m()` (after what no name spells, `list[i]->m()`, it stays `m`) and seeds a positional initializer (`static struct club_ops ops = { "club", 0, club_scout, club_release };`) into value flow.
- `qt-slots.ts` marks `SLOT(name(…))` calls passed and adds a `&Owner::slot` argument as `Owner.slot`.
- A file that does not parse is read again through `readWithBranches(text, cplusplus, read)` with each conditional's first branch; the left-out branches' calls are counted and a second-branch reading's definitions added.

## Macros

- A function-like `#define` outside a function body → `FileAnalysis.macros`, each with the bare calls its body makes (`MacroInfo.calls`; none when the body stringizes or pastes with `#`/`##`; a parameter, member, scoped or declaring name never counts) — [../shared/c-family-macros.ts](../shared/c-family-macros.ts).
- The linker's `macroBodyLinks` gives a call that landed on the macro (own file first, else the one definition its includes reach, `macroDefinition`) those calls as the caller's own: INFERRED links carrying `SymbolLink.viaMacro` (summary and payload slot [10]), resolved in the caller's scope, nested macros eight deep, never through one already on the way. Their line is the macro's use, which does not spell the callee, so the rename plan, caret assertions and the resolved-site sets (`isSpelledCallSite`) refuse or skip them; where a caller's one link to a function has both a macro use and a spelled line, both dedupes keep the spelled line.
- `token-calls.ts` (`tokenCalls`/`defineCalls`/`leftOutCalls`) reads calls off a C-family ANTLR lexer's tokens (`TokenKinds`) where a parse reads no expression: macro arguments, a `#define` inside a function, left-out branches.

## Qt, QML and Qt Designer

- Framework rules `qt` (C++ manifest) and `qt-quick` (QML manifest) live with the plugin that owns the file format.
- QML (`../qml/`, `.qml`, regex, `importTarget: false`, `frameworkImportHints: { QtQuick: "qt-quick" }`) has a reachability model built by [../shared/reachability-kit.ts](../shared/reachability-kit.ts). `QmlCppBridgeResolver` (`qml/dispatch.ts`; `dispatchLanguages: ["cpp", "c", "objc"]`) joins QML elements to the C++/C/Objective-C classes that register them, so a Qt project whose C++ registers QML types needs the bridge even before a `.qml` is discovered.
- Qt Designer forms (`../qtui/`, `.ui` XML, `qtui/index.ts`, the Qt Widgets analog of Delphi's `.dfm`): each file is one screen named by `<class>`, nested `<widget class=… name=…>` elements are its component tree, and `<connections>` wires widget signals to C++ slots (`pushButtonApply.clicked() → DlgPrefEQ.slotApply()`); interactive elements carry the slot name as handler. No functions, classes or imports.

## Reachability, tests, CUDA

- C, C++ and Objective-C share one reachability instance ([../shared/c-family-reachability.ts](../shared/c-family-reachability.ts), a `conventionReachability` spec): a C function behind a header is reached by name (`declaredNames`).
- `CMakeLists.txt` is a `cmake` project root only when it contains a `project()` call (`project-markers.ts`; activation files `CMakeLists.txt`, `conanfile.txt`, `vcpkg.json`); a CMake root registering tests gets `ctest --test-dir build` ([../shared/cmake-commands.ts](../shared/cmake-commands.ts)).
- Control flow: `meta.regexControlFlow` (approximate), node roles from `control-flow-defaults.ts`. `.cu`/`.cuh` are read like C++ (`cuda.test.ts`).
